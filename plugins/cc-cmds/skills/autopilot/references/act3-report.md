# autopilot seat — the morning report (`--report`)


Read the manifest, the run ledger and the report for the named run; for the requirement-decision and frozen-residual bullets only, the design document `## 요소` names; and, when the manifest is absent or the run ledger file carries no line beginning ``- `run` |``, the kickoff trace. Then render in Korean. **Render only — this mode starts nothing and writes nothing.** Whether the ledger file exists is never the test of whether the run started: the report stub is that same file.

Put the dashboard link line at the very top, before every section below: the one line `python3 <plugin root>/orchestrator/dashboard.py url <run-id>` prints, verbatim, or 「대시보드 없음 — python3 를 찾지 못했습니다」 when `command -v python3` finds nothing. This does not break "Render only": `url` reads the server record and `/healthz` and starts nothing, and this seat is outside the gate hook as Step 7's is.

Cover, in this order:

- **결과 요약** — segments planned, merged, **완성-미착지**, parked; where the run stopped against its `종료 지점`; and how the run ended — its end token, the `재킥 원인` of the earliest run-scope row carrying one, and the `종료 부류` of the end row when it has one: `완료` (every termination condition held), `이어받음` (a later run took this one over — name that run from the row's `근거`) or `포기` (a person gave it up). A run with no end token is still open: say so, and do not call it finished because its watchers have gone quiet. Keep 완성-미착지 separate from parked: those segments produced everything they were asked to and had exactly one terminal act blocked, and folding them into "parked" hides the difference between a night that worked and a night that did not.
- **설계 티어 대조** — the tier the run was planned on, beside what the reviews then found. It reads the run ledger's `설계 티어` row, the manifest's `## 실행 계획`, and the ledger's `segment`, `cycle` and `리뷰 기각` rows. Render in this form:

  ```
  설계 티어 — 판정 <판정> → 확정 <확정>[ (사람이 올림)] · 경로 <경로> · 감사 <있음|없음> · 추정 파일 <n> · 선언 파일 <m|미통치>
  근거: <근거 축자>
  무거운 사유: <사유 축자>
  감사 공시 — <스테이지>#<실행 버전> · 경로 <경로> · <최초|재감사> · 고유 <n> · 미보강 <n> · 골격급 <n> · 합성 후보 <n> · 재수렴 <발동|없음> · 감사 판 <12 hex|미상>
  <세그먼트>: 첫 리뷰 P0 <a>/P1 <b> · 누적 P0 <Σ> · 리뷰 기각 <k>건(기각 P0 <Σ>)
  ```

  - `<판정>`, `<확정>`, `경로`, `감사` and `추정 파일` come from the row; a row written before `경로` existed leaves ` · 경로 <경로>` out.
  - One `감사 공시` line per `감사 공시` row of the ledger, in ledger order, its fields copied as the row spells them, `미상` included. `재수렴` reads `발동` when the ledger holds a `stage-result` row with `종류=reconverge` on the same audit key and `없음` otherwise. A run with no such row has no line: a `solo` plan carries no audit, and a run older than the row writes none. Add 「 (사람이 올림)」 when `판정` and `확정` differ: the kickoff's judgment is `판정`, and a person's raise is what moves `확정` off it.
  - `근거` and `무거운 사유` are read from the manifest's plan — `design_tier_rationale` and `design_heavy_reasons` joined by ` / ` — not from the row, which carries them clipped. Leave the `무거운 사유` line out when the list is empty.
  - `<m>` is the size of the union of the `선언 파일 집합` of this run's `segment` rows — files, not rows, so a file two segments declare counts once. With no `segment` row, write `미통치`: no slice was planned, so nothing governs a count to set beside the estimate. A clipped set — `<clip> (전체: <path>)`, or `(전체: <path>)` alone — is counted from the whole value in that file, never from the clip. When that file is gone or unreadable, write `미상(전체 파일 없음)` and do not set the estimate against it.
  - One line per segment that has a `cycle` row: `첫 리뷰` is the `P0`/`P1` of its first `cycle` row, `누적 P0` the sum of `P0` over all of them, and `리뷰 기각` the number of its `리뷰 기각` rows with the sum of their `기각 P0`. A segment with no `cycle` row gets no line.
  - When the plan carries `design_tier_judged` and the ledger holds no `설계 티어` row, write the one line 「설계 티어 — 행 없음(계획에는 판정 <판정>·확정 <확정>)」 from the plan's `design_tier_judged` and `design_tier`, and nothing else in this section. A run whose plan carries neither the row nor the key predates the tier keys: leave the section out.
- **자율 결정 전부** — every `자율 승인` row, grouped by `kind`, carrying the decision, the rejected alternative, and the rationale as recorded. **This is the whole point of the report.** The residual it compensates for — a stage that asked in prose, answered itself, and produced output anyway — is byte-indistinguishable from a correct run through every channel the design permits, so after-the-fact auditability is the only control left. Do not summarize these rows away.
- **사람 없이 쓴 중단 답** — every automatic `중단 답` row: those whose `답한 주체` is `좌석` or `교대`, and those with no `답한 주체` whose `근거` begins with the older prefix `자동 채택(구속-이탈) — `. One line each: the row's `세그먼트` (the run key), its `중단 기록`, the label it chose (`선택지`), its `답한 주체` (`교대` for an older-prefix row), and its grounds kinds read from the row's `근거 종류` — a `교대` row with no `근거 종류`, and every older-prefix row, reads `매니페스트 인가`, because what allowed that answer is the manifest's `구속-이탈` row. Read the kinds from the row, not from the record: the run directory, and the records with it, may already be gone, and the ledger row stays. End the section with the count of automatic `재수렴` answers per key. With no such row, say 「사람 없이 쓴 중단 답 없음」.
- **좌석이 동결한 잔여 항목** — what a design stage's residual ladder left open and the seat froze without a person. Start from the `중단 답` rows whose `답한 주체` is `좌석` and that carry `잔여 판정=`; each names the residual items it froze and their classes (`코드-부재:R2,R3/사람-환경:R1`).
  - One line per item: its `R<n>` and title, its `차단 부류`, the slice that owns it, and its `실패 시 영향` verbatim, read from that `### R<n>.` block of the design document. Put the items whose `실패 시 영향` names the binding tier first. Tag every `사람-환경` or `외부-준비` item 「머지 뒤 사람 확인」: it waits for a person after the merge, and nothing in the run checked it.
  - Under each row's items, one review command line: 「골격을 다시 보려면: `/cc-cmds:design-reconverge <설계 문서 절대 경로> 잔여 동결 재검토 <중단 기록>` — 실행하지 않은 명령입니다」. **It is inert** like the queue's command lines: neither the seat nor the report runs it, and nothing reverts the freeze by itself. A person who wants the review runs it in a session of their own.
  - When the design document is gone or its block for an item is missing, draw the line from the stamp alone — `R<n>` and the class — and say 「설계 문서에서 읽지 못함 — 도장에서만 그렸습니다」.
  - With no such row, leave the section out.
- **사람 답 대기** — every record the shift handed back to a person because it could not carry the answer out: the snapshot's `returned_halts[]`. One line each: the key (`segment`), the record (`record`), the label that came back (`option`), who chose it (`answered_by`) and why it could not be carried out (`reason`), so the reader sees which choice came back from whom. A record that waits because none of its options could be carried out wrote no row and is not listed here — the seat gives that reason when it asks the record next. With no element, say 「사람 답 대기 없음」.
- **설계 팀이 정한 요구 결정** — read from the design document's `## 팀이 정한 요구 결정` section and nothing else: the interview record is not read, and neither the questions asked nor the `← 추천` options taken are counted.
  - (a) 「팀이 정한 요구 결정 M건 (벗어남 D건)」 — M is the number of `### 요구 결정 <n>.` headings in that section, and D the number of those whose `**기록과의 관계**` is `벗어남 — 문 <n>`. The lines of `### 확인된 요구와의 대응` count toward neither.
  - (b) the entries verbatim, the `벗어남` ones first, then every correspondence line that is not `그대로`.
  - (c) when the document's `**상태**` line does not read frozen, 「동결 전 문서에서 읽음」.
  - (d) 「이 목록은 결정한 팀이 직접 적은 것입니다 — 팀이 적지 않은 결정은 여기에 나타나지 않습니다」.
  - With nothing to show, one line of these: 「이 런에는 설계 스테이지가 없었습니다」 · 「lead-solo 런 — 요구 결정은 킥오프 대화에서 물었습니다」(티어가 `lead-solo` 인 옛 계획의 런에서만) · 「문서에 절이 없습니다 — 설계 스테이지가 목록을 남기지 않았습니다」 · 「설계 문서가 없습니다」.
- **도달 감사** — the acts that PASSED and touched something outside this machine, which no other section reports: every exec row whose `도달` is `dev`, `prod`, `배포트리거` or `협업`, every row whose `등급 출처` is `불투명` or `미상`, every row carrying a `표지`, every `dev` row whose `식별자 대조` is `미선언` or `대조불가`, and every read whose `도달` is `prod`. List them prod first. `런로컬` and `-` are reported as a COUNT and not enumerated — they are the bulk and reading them teaches the eye to skip.
- **보류 큐** — every `blocked` row with its `스코프`, `원인`, `사유`, and the re-invocation command line where one was recorded. Group the `act` parks by `도달 판정`: a `dev식별자부재` and a `prod인가없음` are one manifest line apart from being finished, while a `비밀출력` is a form that must be rewritten. Group by scope: an `act` park is one command away from finished, a `cone` park needs its premise repaired first, and a `run` park means the run could not judge a state. **Those command lines are inert**: the driver recorded them and never ran them, and neither does this step. They are for the user's hands.
- **사람 대조 필요** — every report line so marked. These are the ones where the run could not tell "still working" from "stuck", or where an apply's outcome is unknown. Name the preserved worktree path for each apply of unknown outcome; it is the only reproduction of that state.
- **스테이지 종단 부류** — per stage: 정상 완료 / 의도된 park / 산출물 없는 정지 / 공허한 성공 / 크래시 / 적용 불명 / 외부 종료 / 한도 종료 / 한도-형상 회수 / 거절 종료. Call out every `거절 종료` explicitly too: the model refused, the stage was re-attached once, and a second refusal parked its cone with `원인=거절 소진`. Call out every `공허한 성공` **and every `외부 종료`** explicitly; naming the first is what lets it be counted. Call out every `한도 종료` explicitly: a stage that died of the usage limit by itself, disposed of exactly as `크래시` today and counted apart. `외부 종료` is the one class the gate writes about a stage it never classified: the prelude settled a dispatch whose record outlived both its process and its supervisor, with no result envelope to read, so the row says a stage ended unobserved and not how. `산출물 없는 정지` is the value a stage lands on when it *correctly refused to decide for the user* — do not report it as one of the others.
- **정체 라벨** — the stall-label history, replayed from the run ledger by the classifier rather than read from a snapshot. Find the classifier copy through two recorded values, never by deriving a run directory from the run id: (1) the `RUN_DIR=` of the ledger's `run` row; (2) the `plugin-dir` line of `<RUN_DIR>/plugin-pin`; (3) when both exist and `<plugin-dir>/orchestrator/stall-class.awk` can be read, use that file — the pinned copy; (4) otherwise use the installed `<plugin root>/orchestrator/stall-class.awk`. Run `LC_ALL=C awk -v mode=all -v root=<root> -f <copy> <ledger>`, where `<root>` is the absolute logical path `cd "<manifest directory>/../.." && pwd` prints — the derivation the gate uses for a relative report path. With no manifest there is no `run` row, so nothing is replayed. Do not call `gate.sh snapshot` for this: `stalls` carries current labels only and loses every consumed or replaced one, the pinned gate lives in the same run directory, and entering the gate rewrites the run's reap clock. All of it is reading. Render in this order:
  - (i) exactly one source line: 「분류기: 이 런의 고정본」 · 「분류기: 설치본 — 이 런의 고정본을 찾지 못했습니다(런 디렉터리가 회수됨). 판본 <판본>」 · when the pinned plugin directory exists but holds no classifier, 「이 런의 고정본에는 분류기가 없었습니다 — 아래는 설치본의 사후 재생이며 런 중에 전달되지 않았습니다」 · when neither copy exists, 「정체 라벨을 재현할 분류기가 없습니다」.
  - (ii) per segment, each labelled row's `부류`, `사이클` and `원장 줄`, then its `소비 줄` or 「소비 안 됨」. A consuming line proves only that a new plan FOLLOWED the label, not that the plan acted on it — never write 「반영됨」.
  - (iii) mark a current label `현재`. When the segment's last non-empty `상태` is `머지됨` or `완료`, add 「끝난 세그먼트의 라벨」; `park` and `리뷰중` do not take it, because a person can resume such a segment and the label is still the latest review's fact for them.
  - (iv) a replay that prints nothing renders 「없음」; a failure of this item's own awk renders 「정체 라벨: 계산 실패」, never 「없음」.
- **이어받은 인가** — only when the manifest carries a `사전 인가` row whose first field is `이어받은 런=`: the source run id, and its `매니페스트 sha256=` and `인가 기록 sha256=` values as written. When that row carries `좌석 연쇄=`, add one sentence: 「좌석이 연 후속 런 — 연쇄 <k>/<연쇄 상한>, 뿌리 런 <id>, 이전 런의 끝 <원인>」, `<k>`, `<id>` and `<원인>` being the row's `좌석 연쇄`, `뿌리 런` and `원인`, and `<연쇄 상한>` the manifest's `재킥오프` row's. When the report stub carries the seat's reason line (「좌석 재킥오프 근거: …」, written as the stub was created), show it verbatim beside that sentence. When the stub carries adoption lines (「재킥오프 입양: …」 and 「재킥오프 입양 안 함: …」, written as the stub was created), show each verbatim, so the reader sees which unlanded segments this run took over with their pull requests and which it did over. Find the row by that first field, never by its lack of `형태=`, which the interview-record row shares. With no such row, leave the section out.
- **판본** — the `run` row's `판본`, `판본 트리` and `판본 다이제스트`: the commit, the plugin subtree's git tree and the content digest of the copy that actually enforced this run. `(고정 안 함)` means the run was never pinned — it opened before pinning existed, or under the test seam — and is a statement about the run, not a missing value. `(미커밋)` means the subtree was dirty when the copy was taken. To reproduce a pinned version, `git archive <판본 트리> | tar -x` in the plugin repository and check that the result's content digest equals `판본 다이제스트`; a `(미커밋)` version cannot be reproduced once the reaper has collected the run directory. Beside the three values, show the `origin-sync` line of `<RUN_DIR>/plugin-pin` (`RUN_DIR=` from the ledger's `run` row, as for the stall labels), and with it `ff-refused` when `origin-sync` is `원격 끝`: in that case the pin's `method` is `archive-remote` and `판본` is the remote tip commit, not the commit the source checkout stood on, because that checkout could not be fast-forwarded. `시험 봉합` means the run opened with the fetch and fast-forward switched off — say that it opened without syncing to the remote. When the pin file is gone, say the sync result is unrecorded.
- **비용** — the accumulated `cost` rows, and the cycle count against the run's cycle budget. Put **`정산됨(비용 불명) N건`** — the count of `외부 종료` rows — beside the total: a settled stage has no envelope and therefore no `cost` row, so a total shown alone reads lower than what was spent. Where this run has no `cost` row at all, report `비용 불명`, never `0`.
- **계측 필링 건너뜀** — every `계측 필링 건너뜀` row with its `사유` (`자격 없음` · `상한 도달` · `번호 없음` · `조회 실패`) and `트리거`; and every `자율 승인` row with `kind=metrics-filing` (the issues the collector filed, commented on or closed). Where there is no such row, say so — silence here is not "nothing to file".
- **중단 리포트** — two halves, because the rows and the run they are about live in different places. (a) This ledger's rows: every `자율 승인` row with `kind=halt-report` with its `결정` (`등록` · `코멘트`), `런`, `서명`, `이슈` and `담기` — where `담기=실패`, name the command file `<ledger directory>/halt-report.unfiled/<이슈>.md` — and every `중단 리포트 건너뜀` row with its `사유` (`대상 아님` · `자격 없음` · `스코프 부족` · `조회 실패`), `런` and `서명`. These rows are written by whichever run's gate hosted the round, so they usually describe OTHER runs; where there is none, say so. (b) This run's own disposition, from its record `${XDG_STATE_HOME:-$HOME/.local/state}/cc-cmds/halt-report/runs/<run-id>.json` (a run id outside `[A-Za-z0-9._-]` is stored under the first 16 hex of its sha256): one line of `정착 대기` · `대상 없음` · `원장 없음` · `등록 #n` · `코멘트 #n` · `대상 아님:<제외 사유>` · `건너뜀:<사유>` · `미룸 n건` · `담기=포기 #n`, read from its `런 처분` field, or `기록 없음` when the file does not exist. A morning report is usually written before the run settles, so `정착 대기` is the ordinary first reading and not a failure. All of it is reading.

**A run with no manifest, or with no `run` row, is reported from the kickoff trace.** With no manifest, resolve `<base>` by Step 6's rule from the worktree `--report` was invoked in — linked worktrees of one repository share the common git dir and so reach the same base — and read `<base>/docs/pipeline-run/<id>.kickoff.md`, judging its last stage by `### 2b.6`'s terminal rule of `pipeline-sidecar.md`:

- `대상 변경` with `새 base=` → 「이 킥오프는 새 base `<경로>` 로 옮겨 갔습니다 — 그 base 에서 다시 보고를 받으세요」
- `중단` → 「이 킥오프는 1막에서 <시각>에 사람에게 알리고 멈췄습니다」
- anything else → 「이 킥오프는 1막 `<마지막 단계>` 에서 <시각>에 멈췄고 런은 시작되지 않았습니다」
- no trace either → 「이 id 의 매니페스트도 킥오프 흔적도 이 base 에 없습니다」

With a manifest and no line beginning ``- `run` |`` in the ledger, judge by the trace's last stage: `연기` → 「이 런은 연기되었고 아직 기동되지 않았습니다 — 백로그에서 파킹됐는지는 이 보고가 보지 않습니다」 (a deferred record can be parked by the dispatcher, and a parked record is never planned again); `기동 직전` → 「이 런은 기동 직전에 멈췄고 시작되지 않았습니다」; anything else → 「이 킥오프는 1막 `<마지막 단계>` 에서 <시각>에 멈췄고 런은 시작되지 않았습니다」.

**A time the report writes in its own words is shown in the display zone.** Every `<시각>` above is the UTC ISO from the trace or the ledger converted by `bash <plugin root>/orchestrator/display-tz.sh iso <ISO>` (KST unless `CC_CMDS_AUTOPILOT_TZ` names another zone); when the helper prints nothing, write the ISO string as it was. A time inside a ledger row the report quotes as recorded stays as recorded.

**State the report's own limit at the end.** It is authored by the run it describes, so it is powerless against a run that improvises **and also** omits that from its own report. The conjunction being rarer than either part is why this control is worth having — it is not a gate, and the real protection against an irreversible autonomous act remains the permission cutpoints the user set in 5b.
