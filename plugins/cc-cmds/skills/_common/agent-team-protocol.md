# Agent Team Protocol (Shared Rules)

Shared orchestration contract for multi-agent team workflows. **Which skills it binds is a self-evaluated predicate, not a skill list**: it binds every skill whose own SKILL.md directs it to Read this file rather than inlining or paraphrasing it. A team member is a **nameless background task**: the lead spawns it with `Agent` (`subagent_type: "claude"`, **no `name`**, `run_in_background: true`), resumes it across rounds by its `agentId`, and the task **self-terminates** when it returns.

A returning task delivers its round product two ways at once: a **durable witness file** the member writes before returning, and the **ephemeral return text / background completion notification**. The witness is the **authoritative source of truth**; the notification and return text are demoted to **early-wake hints**: the notification can be dropped, duplicated or mis-routed, and a returned `agentId` cannot be status-polled (`TaskGet` answers "Task not found"), so the lead reconciles against on-disk bytes the member alone wrote, never against a notification.

## Spawn

Spawn each member as a nameless background task: `Agent({ subagent_type: "claude", run_in_background: true, prompt: <self-contained assignment> })`. A task does **not** share the lead's conversation — embed everything load-bearing into the prompt (role, round, all inputs the member must act on, plus the witness parameters below). Record the returned `agentId`, the member's `scratchDir`, **its `outputFile`** (the `output_file` path the spawn envelope exposes), the team's **`epoch`**, and the member's **round-1 `witnessNonce`** in the ledger immediately, with the same immediacy (see **Role↔agentId ledger v3**). Spawns are synchronous calls: a spawn error is returned inline and handled inline (no dispatch-failure bound needed).

Before spawning the first member of a team, the lead creates one team witness directory **out-of-tree**, rooted under the driver-exported run directory when there is one and under the state directory otherwise. One command does the whole of it:

```
<plugin root>/orchestrator/cc-team-witness-init.sh <slug>
```

It prints the created directory on stdout and nothing else, so **the printed path is recorded literally** — never `$WITNESS_DIR`, which does not survive to the next Bash call. Root selection, the stage tag, the `mktemp -d` and the `.attempt` stamp all happen inside it.

**Inside a gated run, declare it as `--surface 트리밖쓰기 --reach 런로컬`.** It writes only under the run directory or the state root, and the grading table answers `트리밖쓰기` for this script's own name.

**`<plugin root>` is substituted by YOU before the command reaches a shell**, exactly as it is in the two other places in this plugin that run an orchestrator script from skill prose. It is the directory holding `orchestrator/` and `skills/` — the parent of the skill directory's parent. It is deliberately **not** a shell variable: `${CLAUDE_SKILL_DIR}` is not exported into the shell, so a command written with it expands to an empty prefix and fails quietly on a path that does not exist.

**Run it directly. Never put `bash` (or `sh`, or any other interpreter) in front of it.** The adjudication gate grades an act by the basename of its argv0, so an interpreter in front makes the act a worktree write and the honest out-of-tree declaration is refused.

**If the gate answers `등급 미상` for this script**, the gate adjudicating the run is older than the tree that ships it. Do not reach for a workaround: `bash` in front re-opens the defect, and a bare `mktemp -d` drops the `.attempt` stamp.

**Root.** Under a pipeline run the witness sits beside the rest of that run's artifacts; with no driver exporting `CC_PIPELINE_RUN_DIR` it sits under `${XDG_STATE_HOME:-$HOME/.local/state}/cc-cmds/design`, which the command creates. **Neither root is the system temp dir**: a temp directory can be collected out from under a live team, and a collected witness leaves the lead parking forever or synthesizing a product it never observed.

**Name — the form, stated normatively here.** What the command above mints is:

```
<root>/cc-team-witness-<slug>[.<sanitized stage id>].XXXXXX
```

The cleanup contract's path guard and every reader of a ledger row's `scratchDir` quote this form. `<root>` is the driver's run directory when one is exported and `${XDG_STATE_HOME:-$HOME/.local/state}/cc-cmds/design` otherwise; the tag is omitted entirely when no stage id is exported.

**No new attempt discriminator is minted.** A retried segment gets a fresh scratch dir per attempt and each attempt's ledger starts at `epoch 1`, so `max(epoch)` cannot tell attempts apart. The stage id already carries `<segment>#<attempt>`, so the directory name carries **that id, sanitized** — every character outside `[A-Za-z0-9._-]` replaced, the `#` above all — and the tag is omitted entirely when no stage id is exported. The raw id is additionally stamped once per stage into the directory's `.attempt` (leading dot, no `.md` suffix, so it is hidden from the witness key glob), which makes the directory self-describing to a later reader; with no stage id exported there is no attempt to discriminate and no `.attempt` is written.

Out-of-tree placement makes the two-command boundary gate (`verification.md` §6 — assertion 1 plus the three scoped worktree assertions defined there) self-evidently satisfied — even in a user project where `docs/` is tracked, the witness adds **0 surface** to `git status`. Each **fresh** team (the `design` Step-5 walkthrough team, the Step-6 refinement team) gets its **own** nested directory from a fresh run of the `## Spawn` command above — never a hand-written `mktemp -d`, for the reasons that section gives — anchored per-row in the ledger as each row's `scratchDir` (see **Role↔agentId ledger v3**) so it survives compaction. Each fresh team is also assigned a **monotone `epoch`** (generation index — the Step-3 discussion team is `epoch 1`; each subsequent fresh team — a Step-5 walkthrough team, a Step-6 refinement team, a `design-analyze` Step-8 re-composition — takes `epoch := max(disk epoch, 0) + 1`, **re-derived from the on-disk ledger at spawn, never from an in-context counter** (a counter lost to a compaction would re-stamp a colliding epoch); the `max` for the **increment** is taken over **all** rows **including `aborted`** so the generation index stays monotone-unique even across a fully-aborted prior team), stamped on **every one of its rows** at spawn in the **same recording window as `agentId`/`scratchDir`** (no new exposure window). The current team is then identified from disk as **`max(epoch)` over non-aborted rows** — the **increment domain is all rows** (uniqueness) while the **selection domain is non-aborted rows** (current team) — a derived quantity with no separate pointer that could desync from the rows, so the scope survives a compaction that leaves no `state=running` row.

**Re-convened prior team — `epoch` re-stamp.** A team from an earlier generation that is legitimately re-convened for a later phase — a *permitted resume*, whose closed enumeration is owned by the calling SKILL.md — does **not** keep its original `epoch`. Before the first resume of that phase the lead re-stamps `epoch := max(disk epoch, 0) + 1`, re-derived from the on-disk ledger with the `max` taken over **all** rows including `aborted`, onto **every row of the re-convened team**: one single-row Edit per row, all in one contiguous window. Like `witnessNonce`, `epoch` is **gate material rather than a dispatch certificate**, so it is written **before** the resume; the `round/phase` flip still follows the resume, leaving resume-ACK ordering unchanged. A partially re-stamped ledger is simply the roster's existing mode-(iii) partial presence and fail-closes gracefully via `AskUserQuestion` — the safe direction, not a new failure mode. **Never hard-code the resulting value**; it depends on how many teams intervened.

Without the re-stamp the roster resolves to the most recent **fresh** generation, and self-heal resumes **foreign-role** `agentId`s and consumes their output as this phase's product — fabrication.

### Team size budget

The single source of truth for how many **domain-perspective roles** a team carries. It is a ceiling with no floor — a small team needs no defence, and the measured failure mode is over-staffing, not under-staffing.

- **Up to 4 roles** — no justification needed.
- **5 roles** — allowed, but the proposal must name the domain the fifth role covers that no other role does.
- **6 or more** — not available. Work that seems to need it is scope to surface to the user, not roster to grow.

**What binds (self-evaluated predicate, not a skill list).** The budget binds any step that **chooses how many roles a team has at composition time**. A skill that writes its role count as a literal is outside it — there is no choice for the budget to constrain. Stating this as a predicate rather than an enumeration means a new skill inherits it without an edit here, and a skill that later replaces a literal with a choice comes under it automatically.

**Coordinator-class carve-out — meta/coordination roles are not counted.** A role whose job is orchestration rather than a domain perspective — a scope coordinator, an analysis coordinator, anything else of that class — sits outside the count. Such a role earns its seat precisely in the largest scopes, which is the tail where the over-staffing observation does not hold and where a naive ceiling would force the implementer either to break the budget or to drop the coordinator. Because it is never counted it can never push a roster over budget, and therefore never needs a pairing under the ADD gate below.

**Shrinking is a real operation.** `_common/team-upgrade-analysis.md` carries `REMOVE` and `MERGE` next to `ADD` / `SPLIT-REPLACE` so a roster can go down as well as up; a ceiling shipped without them would silently freeze `SPLIT-REPLACE` (which adds a seat) and become unenforceable. Neither may be proposed on cost, token-budget, or headcount grounds alone — that rule is what keeps a budget from eating quality. An `ADD` of a **domain-perspective** role that would exceed the ceiling must be paired with a `REMOVE` or a `MERGE`.

## Witness file (member-written, durable, atomic publish)

- **Layout — per-member-per-round separate files.** `${scratchDir}/{role-slug}.round-N.md` for discussion rounds; `${scratchDir}/{role-slug}.{phase}.md` for phase work (fidelity / walkthrough / refinement / coherence / fanout). A shared single append log is **FORBIDDEN** — parallel members appending to one file in the same round interleave and corrupt it. Separate files shrink the racing-writer surface to a single `(role, round)` path.
- **Write discipline (MUST).** Build the full round product **plus the trailing sentinel** in a **single hidden per-attempt temp**:

    ```
    T=$(mktemp "${scratchDir}/.{role-slug}.{round/phase}.XXXXXX")
    ```

    (same directory → same-filesystem rename atomicity; the temp has no `.md` suffix and a leading dot, so it is hidden from the default glob and never appears in the `{role-slug}.{round/phase}.md` key list). Then, as the **final action before return**, publish atomically:

    ```
    mv -n "$T" "${scratchDir}/{role-slug}.{round/phase}.md"
    ```

    `mv -n` is stat-then-rename, not atomic no-clobber, so a same-round zombie-vs-respawn pair can race the same target. The guarantee is instead: (1) whichever rename lands, the published file is a **same-nonce completed** product, so the reader always observes a valid completed witness — **any-winner-is-a-valid-completed-witness**; and (2) **no temp is ever self-deleted** — a losing or interrupted temp stays in place and is swept by teardown. An orphan `.{role-slug}.{round/phase}.*` temp is harmless: floor-read and recovery only look at the non-temp key path (`{role-slug}.{round/phase}.md`).

- **Sentinel + nonce.** The last line of the published file is the sentinel carrying the lead-injected per-(member, round/phase) nonce:

    ```
    <!-- cc-witness: {role-slug} {round/phase} complete {nonce} -->
    ```

    The lead generates `{WITNESS_NONCE}` per **(member, round/phase)** as a **compound `<round/phase-token>:<hex>` value** — the `{round/phase}` sentinel token (`round-N` / phase name), a literal colon, then a hex from `openssl rand -hex 8` — and injects the whole value into the task-assignment header alongside `{WITNESS_PATH}`. The prefix is the **durable minted-round tag** the mint-vs-reuse disk predicate reads; only the hex carries entropy. **The nonce comes from `openssl rand`; the lead never generates it itself.** The member echoes the injected nonce verbatim into the sentinel.

- **No same-round rewrite.** A published witness is **never** overwritten by the contract: a revision is a new round (a new file). The only writers that can target an already-published path are a same-round zombie and its respawn, and both emit the same-nonce completed product.

## Completion predicate `witness_present(member, round/phase)`

Holds **iff all three conjuncts hold**:

1. `test -f {WITNESS_PATH}` — the non-temp `(role, {round/phase})` key file exists (fast pre-gate).
2. The file's **last non-empty line** (strip trailing blank lines / newlines before comparing) == `<!-- cc-witness: {role-slug} {round/phase} complete <nonce> -->`. This catches an **incomplete-tail** write; it cannot tell an atomic publish from a completed direct-write, so that rests on the member's temp+`mv -n` discipline (the header MUST).
3. The filename's `{round/phase}` key == the sentinel's `{round/phase}` key (key consistency — `round-N` matches `round N`, a phase name matches itself) **AND** the sentinel's nonce == the lead-injected per-(member, round/phase) `{WITNESS_NONCE}`.

Existence alone is necessary but **not** sufficient — the sentinel makes the predicate **fail-CLOSED on a write-discipline slip** (existence-only would read a torn direct-write as complete → fabrication, i.e. fail-OPEN). The gate reads **only** this specific key path and its last line; it **never** references the notification, the return text, or `agentId` identity.

## Completion signal (hints only)

The background completion notification and the resume tool result are **early-wake hints** — they tell the lead _when to go look_, never _what was produced_ and never _that a round is done_. Do not look for `[COMPLETE]`/`[IN PROGRESS]` prefixes or session-text echoes — they do not exist in this model. Round completion is established **only** by `witness_present(member, round/phase)`.

**The completion notification carries one fact that is not a hint: the member's task has RETURNED.** A returned task's transcript is closed and its `output_file` will never grow again, so a member whose notification has arrived and whose witness is absent is not "still working" — it is a member that returned without publishing, and no amount of waiting changes that. The reconcile ladder below has a dedicated arm for it (**Returned-without-witness**), and it fires on the notification itself rather than after K byte-stable re-entries.

## Multi-round (resume + context re-injection)

A one-shot isolated `Agent()` per round is forbidden — the retained-context, multi-round cross-review/convergence loop is what makes this a _team_. Round 1 produces; Round 2+ cross-reviews with peer findings. **How many rounds a team drives is defined once in `### Round budget` below** — no other file states a round count except through a carve-out that names that section. Resume a member by sending to its `agentId` (`SendMessage` to the agentId continues the task with its context intact). On every resume, the lead **re-injects the load-bearing context** — quote peer findings **verbatim** and do not trust retained context for load-bearing data.

**Declared exception — the independent-replicate fan-out.** The `### Round budget` default assumes cross-review makes the product better, which holds wherever the members are collaborating toward one answer. It is **inapplicable** where the members are deliberately **independent replicates** measuring the same frozen artifact, because cross-review is exactly what destroys their independence: a member that has seen a peer's finding is no longer a replicate, and the reinforcement statistic the caller derives from agreement becomes meaningless. `design-audit`'s reader fan-out is that shape and is the one declared exception — single round, no resume, `SendMessage` deliberately not loaded so the resume is tool-unavailable rather than merely forbidden. A skill claiming this exception must state it in its own control-flow invariants; the exception is named here so this file does not silently contradict a shipped skill. Everything else in this contract — spawn, witness, ledger, reconcile ladder, escalation — applies to it unchanged.

### Round budget

The single source of truth for how many discussion rounds a team drives. Consuming skills point here instead of restating a number; a skill that deliberately carries a **different** value states an explicit carve-out sentence naming this section, so the divergence is legible as intent rather than drift.

- **Default = 2 rounds.** Round 1 produces, Round 2 cross-reviews. This is where the measured value sits: across the judged sample, Round 2 changed the outcome in the large majority of sessions.
- **Hard cap = 3 rounds.** No team drives a fourth discussion round. Needing more is a signal to surface the impasse to the user, not to keep spending.
- **Round 3 is a condition, not a schedule.** It opens on exactly two entry paths, and on neither of them does the lead adjudicate emptiness from a member's prose:
    1. **A member names a concrete, actionable measurement it has not yet run** that would settle a contested peer claim. Only the member knows whether it holds such a measurement, so the member states it — the lead does not infer it. A text-vs-text re-review with no new measurement is a ratification ritual and does **not** open Round 3.
    2. **The lead's pre-save sweep produced a refuting verdict.** A sweep refutation is itself the product of an executed measurement rather than a re-review, so it satisfies the narrowing's intent while giving the refutation somewhere to go. Without this path a refutation found by the sweep would fall straight through to `AskUserQuestion` or be dropped silently, and a draft with refuting evidence against it could still be saved.

The narrowing moves the judgment to where the knowledge is: the lead no longer grades whether a member's stated blocker is substantive, and the member instead reports whether it is holding an executable measurement.

## Convergence

Convergence is by **witness collection**, not live polling. After cross-review, resume each member once with a convergence prompt (re-inject current consensus + open conflicts); a member's round is converged-and-collected only when its round witness is `witness_present`. Batch the resume *sends*; keep one large resume per member per round and stay inside `### Round budget` (each member's ledger flip is still its own separate single-row Edit after that member's resume — see the dispatch↔flip atomicity rules). The convergence resume is itself a fan-out: the dispatch-completeness gate runs before collecting, so a member dropped from the convergence resume cannot be silently read as converged.

## Turn economy (batch independent calls, reuse one read digest, absolute paths)

What a team costs is not mostly what its calls do — it is how many responses they are spread across, because every turn re-reads the history before it.

- **Issue independent calls in one response.** Two calls are independent when neither's arguments depend on the other's result. Split a response at a real dependency and nowhere else — not at a topic change, not because the calls touch different files. This binds Bash, Read, Edit and `Agent` spawns alike; the batched resume *sends* of `## Convergence` above are one instance of this rule, not an exception to it.
- **Reuse one `--snapshot-digest` across up to three READ `exec` calls in the same response.** **Three** is the bound because a shared digest has to stay inside the gate's ancestry window (`GATE_ANCESTRY_WINDOW=8`). The cap is on **reads**; an acting call carries `--emit-digest` and the next one reads the emitted value. A digest that went stale is refused with exit 4 and costs one extra ledger row — that is the designed failure, not a reason to re-snapshot before every read.
- **Pass absolute paths; never prefix a command with `cd`.** `grep`, `sed`, `ls` and `python3` all take a path argument, so `cd X && …` buys nothing and costs a shell. Under a gated run it costs more than a shell: the working directory is not part of the act's record, so a `cd`-prefixed command is recorded in a form a later reader cannot re-run.
- **Never wrap a command in `bash -c` to batch it.** The adjudication gate grades an act by the basename of its argv0, so a wrapper hides the real verb and a network call lands in the ledger as a worktree write. Batching means several calls in one response; it never means several commands inside one call.

## Dispatch-completeness gate (roster-vs-round, pre-wait)

The witness-collection wait (Convergence, and the happens-before `확인` step) keys on witnesses *arriving*, not on whether every roster member was *re-dispatched* this round. A resume fan-out that silently drops a member leaves the wait parked forever on a witness that will never come, and the reconcile ladder cannot rescue it: its `state=running` residual scan never enters a row still at the prior round (`done@(P-1)`, where `P` is the round/phase the wait is over and `P-1` is the immediately prior token, not arithmetic). This gate is the **dispatch-side dual** of the happens-before gate and closes the hole upstream of the ladder.

**Runs as the first step of every pre-wait / re-entry.** This gate is the **first action of the reconcile-ladder re-entry sequence below**, ordered strictly **before** the per-member disk-first floor-read and the liveness ladder, and it runs on **every** pre-wait entry — the first dispatch of a round, and every post-compaction / cross-session re-entry / `state=running` residual scan. It is roster-wide: it fixes *who* the wait is over before the wait inspects each member.

**Composition-time scoping (`### Team size budget`).** The headcount ceiling binds **at composition time only** and is never applied retroactively to an existing roster. A lead that re-enters a ledger carrying more roles than the ceiling converges that team as it stands; it does not remove a row (which breaks the dispatch-completeness gate below) and does not flip a surplus row to `aborted` (which emits a false absence annotation for work that really happened).

**Round-entry scoping (`### Round budget`).** The round trigger is evaluated **at round entry only** and never invalidates a round already in progress. A lead re-entering a ledger whose team already ran more rounds than the budget accepts it and converges it as-is — lenient reader, strict writer (`verification.md` §3.4: untouched lines are never migrated); a lead entering a **new** round is strict.

**Roster (disk-derived, current-team-scoped, aborted-excluded).** The participant set is re-read fresh from the ledger on disk on every entry — never an in-context roster. **Before scoping by `max(epoch)`, evaluate a 3-way epoch-mode precondition over the non-aborted rows**: (i) **uniform presence** (every non-aborted row carries an `epoch`) → the roster is every ledger row with **`state ∈ {running, done}` whose `epoch` equals `max(epoch)` over all non-aborted rows** (the current team's generation); (ii) **uniform absence** (no non-aborted row carries an `epoch` — a single-team skill, or a legacy pre-v3 ledger) → the roster is **epoch-agnostic: every non-aborted `state ∈ {running, done}` row** (exactly the pre-epoch behavior — a single generation needs no scoping, so this is safe, and it is what keeps single-team skills at zero epoch edits); (iii) **partial presence** (some but not all non-aborted rows carry an `epoch` — a compaction-mid-spawn partial stamp or a half-rolled-out multi-team skill) → **fail closed via `AskUserQuestion`** (below), because `max(epoch)` silently dropping an epoch-less current-team row is exactly the dispatch hole this gate exists to close. In all three modes **`aborted` rows are excluded** — **except that if no row is `state=running` AND no row is at `round/phase == P`, the roster is empty and the gate passes** (zero-running rule; the 3-way epoch precondition above is evaluated **first** and short-circuits, so a mode-(iii) partial-`epoch` fail-close fires before this zero-running check — the intersection partial-`epoch` ∧ zero-running is an accepted-residual corner where either verdict is safe, so this ordering is for executability, not correctness). The zero-running check ranges over the **non-aborted** rows and is evaluated **before** the `max(epoch)` scoping, so a between-teams entry empty-passes. The roster is **all** current-epoch rows regardless of round token (running ∪ done), so an intra-team `done@(P-1)` laggard is included — scope by team (`epoch`), never by round token. This roster is correct only because every Case-1 exclusion is routed to `state=aborted`. A whole-round total drop is disk-indistinguishable from between-teams and is an accepted residual owned by the driving step; round-1 spawn-completeness is out of scope.

**Pre-wait predicate.** Before entering the wait for round/phase `P`, re-read the ledger and assert, over every roster row:

    row.round/phase == P

`round/phase == P` is **string-equality on the same `{round/phase}` token the sentinel/nonce is keyed on** (`round-N` matches `round N`; a phase name matches itself), so the gate works uniformly for discussion rounds and for the `fidelity` / `walkthrough` / `refinement` phases. Under the resume-then-flip ordering the round token alone is the dispatch certificate — the flip writes `round=P` only *after* a resume was issued, so `round==P ⟹ the resume was issued **or** a round-P witness was already collected` (the two self-heal branches below). A row still at a prior token (`round/phase ≠ P`) is **undispatched** → self-heal (below) → re-evaluate (the string-inequality `≠P` also formally covers a row *ahead* of `P` — unreachable under sequential lead-driven advance, but handled for free rather than assuming a `<` order); loop until the predicate holds for **every** roster row, then enter the wait. A row already at `round==P` is **dispatched** regardless of its `state`: `running@P` = dispatched-and-still-working (hand it to the reconcile ladder if its witness stays absent — dispatched-but-wedged is the ladder's job, not the gate's), and `done@P` = dispatched-and-already-collected (nothing to redo). The gate and the ladder partition the failure space by the round token — gate owns `round/phase ≠ P` laggards (resume-recover, context-preserving); ladder owns `round==P` no-witness rows (respawn) — so they never double-fire.

**FORBIDDEN — `∧ state==running` conjunct.** The pre-wait predicate is the round token **alone**: the conjunct false-catches every collected `done@P` row, including the one the self-heal-consume branch produces, and makes the loop **non-terminating**.

**Self-heal (resume, never respawn).** On catching an undispatched row (`round/phase ≠ P`), the **first** action is the disk-first witness floor-read for `(member, P)`:
- **Witness already present** (a resume that ran and completed but whose round-token flip was lost to a compaction): consume it — record the row `done` + last-return from the witness content (the normal `기록`) **and** recover the round/phase token (`P-1 → P`), which vanilla `기록` does not do. **No redundant dispatch.** Emit one Korean line — `누락된 팀원 산출물 수집(재파견 없음): <role>` (an accurate collection notice; nothing is dispatched on this branch).
- **Witness absent**: **resume** the member (`SendMessage` to its existing `agentId` — context-preserving) and write the flip. Recovery is a resume, **never** a respawn, which would destroy the member's retained rounds. Emit one Korean line — `누락된 팀원 재파견: <role>` (this is the only branch that re-dispatches).

Escalate (inline `AskUserQuestion`) only if the resume or the flip Edit itself errors — a resume error is returned inline, as at first spawn. A *successful* self-heal advances the row to `round==P`, so the loop exits and the reconcile ladder owns what follows.

**Dispatch ↔ flip atomicity (resume-ACK, never resume-INTENT).** The resume and its ledger flip are two tool calls, not one atomic act; correctness rests on **ordering + under-claim semantics**, not on atomicity across the pair:
- **Order: issue the resume FIRST, then write the flip.** The flip is the durable **ACK** that a resume was issued — never an **INTENT** to resume. A flip-before-resume that then lost its resume to a crash/compaction would read `round==P` for a member that was never sent → the gate false-passes and the stall returns; the ordering forbids this.
- **`witnessNonce` is written before dispatch; mint-vs-reuse is a disk predicate on the nonce's own round-tag.** The `witnessNonce` is not the dispatch certificate (the round token is) — it is the material the `witness_present` conjunct-3 re-derives against, so it is written into the row **before** the resume/spawn it belongs to, surviving a compaction that drops the flip. Because the nonce value is compound `<round/phase>:<hex>`, it carries its own **minted-round tag**. The `{round/phase}` token contains **no `:`** — the round token is `round-N` and a phase name is a **colon-free identifier** (a per-skill parameter each SKILL.md MUST keep colon-free) — so splitting the compound nonce at the **first** `:` unambiguously separates the tag from the hex. On dispatching a row for round/phase `P`, read the recorded `witnessNonce`, split off the tag at the first `:`, and: **tag ≠ `P` → mint a fresh compound nonce `P:<new-hex>`; tag = `P` → reuse the recorded value verbatim** (an initial spawn has no recorded nonce → trivially tag ≠ `P` → mint). This one disk predicate covers both directions: (1) a round-advance-dropped member's self-heal (recorded tag `(P-1) ≠ P`) → mint → per-round freshness restored (a member cannot pre-publish a future round's witness — forgery defense); (2) an interrupted convergence resume already at `P` (recorded tag `P`) → reuse → the already-published `P` witness is protected (`mv -n` never orphaned). The `round/phase` ledger column is written *after* the resume and therefore lags the nonce across the write-nonce→resume→flip window — it is **never** used as the tag; the tag lives inside the nonce value where it is co-written atomically with the hex.
- **The `round/phase` column is a conservative under-claim.** It may lag reality (read `round/phase ≠ P` while a resume is already live → a benign double-resume: both dispatches target the same `{WITNESS_PATH}`/`{WITNESS_NONCE}`, and `mv -n` + same-nonce gives any-winner-is-a-valid-completed-witness); the round token never advances to `P` for a resume that was not issued. Under-claim = fail-toward-redispatch = safe. A compaction between the resume and the flip therefore re-catches the row on the next entry (a benign double-resume), never a false pass.
- **The flip is one atomic ledger-row Edit**, carrying `round/phase → P`, `state → running`, and the full `stallMark` reset **together** — never split across Edits. Single-row-Edit indivisibility is the same guarantee the ledger already relies on for the `lastBytes`/`lastBytesPathTag` co-write.
- **A batch multi-row "flip all at once" Edit is FORBIDDEN.** The resume *sends* may be batched, but each member's ledger flip is its **own separate single-row Edit issued after that member's resume** — a batch flip invites flip-before-resume at batch granularity, the over-certification the resume-first ordering forbids. Physical *adjacency* of a flip to its resume is not required.
- **The flip touches `{round/phase, state, stallMark}` — plus `outputFile` when the resume envelope exposes one.** A cross-round resume keeps the same `agentId`; the flip **refreshes `outputFile` from the resume envelope whenever the resume exposes one**, so the gate does not rest on the harness preserving the path.
- **The gate never touches `thinReturns` on a non-dispatch.** A missed dispatch is not a thin *return* and must not feed the Case-1 counter; the witness-present consume branch writes the real `last-return` per the normal `기록`, and the witness-absent resume+flip path touches no `last-return`.
- **`lastBytes:=∅` on the flip is required.** A resume keeps the same `outputFile`, so the path-tag invalidation does not fire on its own and the first post-resume read would false-WEDGE a healthy resume against the prior round's byte-count.

**Reset on every cross-round resume.** Every cross-round resume/flip zeroes `reentryCount` + `unavailStreak` + `emptyStreak` + `growthStreak` and sets `lastBytes:=∅` — each round is a fresh witnessing obligation — while **keeping** `agentId`/`outputFile` (unlike a respawn, which mints new ones).

**Classification.** Hard-MUST protocol prose, not a lint-enforced `## Control-Flow Invariants` block: this shared file is Read by every skill under the opening predicate, so a per-skill CFI copy would drift once per reader. It adds **no** new turn-yield semantics, and the one Korean line is a progress notice, not an escalation surface.

## Reconcile ladder (witness-absent re-entry)

- **Roster gate, then disk-first check.** On entering a round-N reconcile (and on every cross-session re-entry / `state=running` residual scan), the **first** action is the roster-wide **dispatch-completeness gate above** — catch any `round/phase ≠ P` laggard and resume + flip it — and only then, per still-absent member, the disk-first floor-read of that member's witness. If it is already `witness_present`, treat it as done and consume it — **no respawn, no re-entry count** (this absorbs a notification that landed between the member's return and the ledger flip across a compaction).
- **Liveness acquisition (byte-count only, never content).** A member's liveness signal is the byte-size of its harness `output_file` — the path is the durable `outputFile` ledger column recorded at spawn (a symlink to the member's JSONL transcript). Read the **size only**, never the content:

    ```
    current_bytes=$(wc -c < "$OUTPUT_FILE" 2>/dev/null) || current_bytes=UNAVAILABLE
    ```

    Availability is judged by **exit status, not by the value**: exit 0 + integer = available; nonzero exit (path absent / dangling symlink / EACCES) = `UNAVAILABLE`. The lead **never** `cat`s or Reads `$OUTPUT_FILE` (that would overflow context). `wc -c` is the normative portable form; `stat -L -f '%z'` (BSD) / `stat -L -c '%s'` (GNU) are `lint-bash-portability`-divergent idioms and, if used, require a same-line `# lint-bash-portability: disable=…` suppression.

- **Tri-state liveness verdict (ALIVE / WEDGED / UNKNOWN).** After the disk-first witness floor-read fails, compute the verdict from `(availability, current_bytes vs durable lastBytes)`. The durable `stallMark` block holds `{reentryCount, lastBytes, lastBytesPathTag, unavailStreak, emptyStreak, growthStreak}`; `lastBytes` is read against `lastBytesPathTag` (the `outputFile` path the baseline was read from) — on every read, `lastBytesPathTag ≠ current outputFile` ⇒ `lastBytes := ∅` (this cycle is un-baselined: a respawn's new path self-invalidates the baseline; a same-path compaction preserves it).
    - **ALIVE** — available ∧ (`current_bytes ≠ lastBytes`, or `lastBytes = ∅` warmup): progress. The transcript is append-only, so `current_bytes > lastBytes` is the normal case; a rare `current_bytes < lastBytes` (transcript truncation / a new generation) is also ALIVE, keeping the verdict function **total** over every available byte-count. Reset `reentryCount = 0`, `unavailStreak = 0`, `emptyStreak = 0` (reaching available clears the ∅/vanished conditions), **increment `growthStreak += 1`** (available-but-witness-absent growth is benign-but-unproductive — see the babbling escalation below), set `lastBytes = current_bytes`. Persist the row atomically. **Death cannot fire.**
    - **WEDGED** — available ∧ `current_bytes == lastBytes`: no progress. `reentryCount += 1` (monotone, persist-before-next-read), `unavailStreak = 0`, `emptyStreak = 0`, `growthStreak = 0`. Persist the row atomically.
    - **UNKNOWN** — `UNAVAILABLE`: liveness indeterminate. Do **not** touch `reentryCount`. **Unavailable ≠ wedged ⇒ ask, never auto-kill.** **K (the `reentryCount` threshold) is a WEDGED-death-only gate; UNKNOWN escalation is K-independent** — K-gating UNKNOWN would deadlock, because an ALIVE→vanish trajectory resets `reentryCount` before vanishing; a count carried across an UNKNOWN run is harmless because a kill requires the **current** verdict to be WEDGED. UNKNOWN splits (per the S8 rule below) into `non-∅ + stat-fail` (vanished) and `∅`, each escalating on its own debounce streak independently of K; both sub-states also set `growthStreak = 0`.
- **Death verdict** = all three: (i) durable `reentryCount ≥ K (=3)` — _a floor on attempts, not a sufficient condition on its own_; (ii) the **current** verdict is WEDGED (available + byte-stable); (iii) a FINAL `witness_present` re-check, **atomically adjacent to the `TaskStop`**, is still absent. **Growth always holds a veto**: any ALIVE read resets `reentryCount` to 0. An absent/dangling `output_file` is UNKNOWN, never a death vote.
- **lastBytes is durable + path-tagged.** `lastBytes` and its companion `lastBytesPathTag` are durable and written **together** in the atomic `stallMark` block, in one single-row Edit (the lead is the only writer). The baseline thus self-invalidates against respawn (new path → tag mismatch → ∅) and survives a same-path compaction (K stays reachable).
- **Field durability classification.** Durable `stallMark = {reentryCount, lastBytes, lastBytesPathTag, unavailStreak, emptyStreak, growthStreak}` (6 fields) lives in the ledger row; only `current_bytes` is **lead-LOCAL ephemeral** (recomputed from `outputFile` each re-entry, never stored in `stallMark`). **All three escalation debounce counters (`unavailStreak`, `emptyStreak`, `growthStreak`) are durable** for the same reason as `reentryCount`: ephemeral, a compaction would re-zero them and the threshold (2 / M / G) would never be reached. The counter and the baseline share one durability class: a durable counter with an ephemeral baseline re-zeros on every compaction through the ALIVE warmup, and a wedged member never reaches K.
- **Returned-without-witness → resume first, K does not apply.** When a member's completion notification arrives (the harness task id is that member's `agentId`), floor-read its witness **in the same turn**. Present → consume it as done. Absent → the member has returned without publishing, and the byte-count ladder above would only ever read WEDGED against it, so waiting for K re-entries is waiting for nothing. Resolve it in that turn: `SendMessage` the same `agentId` the fixed message "Publish your witness now, or name where you are blocked in one line." — **at most 2 times** — and if the witness is still absent after the second, go to **Death → same-round respawn** below (no `TaskStop`: the task already ended; same `{WITNESS_PATH}`/`{WITNESS_NONCE}`, inputs re-injected), **except in the declared independent-replicate fan-out above, which forbids resume and does not load `SendMessage`: there no message is sent and the respawn follows detection at once.** Count the resumes as a `witness-nudge <n>/2` token at the head of the row's `last-return summary`, cleared on respawn — never in `stallMark.reentryCount`, which the resumed member's first ALIVE read resets to 0. A member that has been sent the message is a task the harness holds again; a respawn is recorded in the row **before the turn ends**. A respawn that also returns without a witness is Case 2 (below): the ask under seat dispatch, the `case2-respawn-dead` stop point under an unattended arm. The ladder has no wake source of its own: once every live task has returned, a headless process **exits** with whatever rc the turn had and a seat's lead never re-enters, so the lead resolves such a row in the turn that learned of it.
- **A turn never ends with a returned member still `running`.** Corollary of the arm above, stated as its own rule because it is the one the headless case actually needs: at every turn end during a round's wait, every `state=running` row must be a task the harness still holds. A row whose notification has been seen and whose witness is absent is resolved — witness consumed, or respawned — before the turn ends, never carried into "I will wait for it" prose. Reading the member's return text and noting that it is waiting for something is not a resolution; the return text is a hint, and a member that said it is waiting has returned.
- **Death → same-round respawn.** `TaskStop(agentId)` → respawn into the **same round** (round counter NOT incremented; same `{WITNESS_PATH}`, same `{WITNESS_NONCE}`, inputs re-injected — the nonce is per-(member, round/phase) so the respawn reuses the same value, and a surviving zombie + the respawn racing the same no-clobber target with the same nonce both yield a same-nonce completed witness whichever wins → any-winner-is-a-valid-completed-witness determinism). A respawn is a **new** background agent with a new `agentId` and a new `output_file`, so on respawn **update the ledger row's `agentId` and `outputFile`** and **reset the whole `stallMark`** (`reentryCount = 0`, `lastBytes = ∅`, `lastBytesPathTag = ∅`, `unavailStreak = 0`, `emptyStreak = 0`, `growthStreak = 0`). `lastBytes = ∅` forces the first post-respawn read to ALIVE-or-UNKNOWN (never WEDGED), so the dead agent's frozen final byte-count cannot false-kill the healthy respawn. Soft signals (`output_file` growth, early-wake) are acceleration hints, not the gate.
- **S8 — `outputFile = ∅` spawn-race distinction.** An `outputFile` still `∅` (the harness has not populated the path yet) differs from "a path that existed and vanished" (both `stat`-fail). UNKNOWN splits accordingly: **`∅` ⇒ abstain + a separate ∅-tolerance ceiling** — increment durable `emptyStreak += 1` (and set `unavailStreak = 0`); at `emptyStreak ≥ M` escalate via `AskUserQuestion`. **`non-∅ + stat-fail` (vanished) ⇒ durable `unavailStreak += 1`** (and set `emptyStreak = 0`); at `unavailStreak ≥ 2` (consecutive debounce) escalate, K-independently. Both streaks are **strict-consecutive** (entering one sub-state zeros the other). `M = 5` is the **spawn-race tolerance ceiling** (the same benign-but-unproductive family as `G (=5)`: ask after N un-productive re-entries, never kill).
- **Respawn also dies → Case 2 (never-returns).** `AskUserQuestion` menu = {① respawn into the same round again / ② **keep waiting** — re-enter after an additional grace period (always floor-read the witness first) / ③ annotate the missing member explicitly and partial-synthesize from the remaining witnesses (an explicit absence record, not fabrication) / ④ abort the workflow}. Per the happens-before gate, the chosen option gates round N+1: ③ closes round N as partial and proceeds to N+1, but the missing member's ledger row is set to `aborted` (it was `TaskStop`-ed), **not** `done`, and its last-return records the explicit absence annotation (a witness-less `done` violates the anti-fabrication rule and is forbidden). An `aborted` row does **not** re-enter the `state=running` residual scan, so a witness this member publishes _after_ the abort is intentionally never consumed — the partial close is final, and the N+1 absence annotation is authoritative even if a late witness later appears on disk (this is a conservative under-claim, never a fabrication).

## Cross-round happens-before hard gate (no look-ahead)

A multi-round team injects the prior round's peer findings **verbatim** into the next round's prompt → a dropped round-N witness is a concrete fabrication channel. The order is a **MUST** (no boundary batching):

1. **확인** — `witness_present` for **every** roster member (the disk-derived, **current-team-scoped** roster of the dispatch-completeness gate — see its **Roster** definition above, `max(epoch)` team; not a memory-held subset the lead recalls resuming), which the pre-wait dispatch-completeness gate has already certified was resumed into round N;
2. **기록** — read each witness and record `state=done` + last-return in the ledger;
3. **only then** resume round N+1.

If round N was closed as partial via Case-2 option ③, the missing member's round-N+1 verbatim-injection slot **carries the explicit absence annotation** (no empty slot, no silent omission) — so the N+1 peers see that slot as "no report (missing due to respawn failure)" and avoid a soft-fabrication that assumes a complete peer that never existed.

This rule is **hard-MUST protocol prose**, not a CFI block, for the reason the dispatch-completeness gate's **Classification** gives.

## Anti-fabrication (disk is the SOT)

- **Sole-authorship anchor.** The lead **never** writes a member's witness — the whole guarantee rests on this one fact.
- **Fail-closed hard gate.** The lead **never** extracts round content from the return text or the notification. A round-N witness that is absent or partial (no trailing sentinel) → **same-round respawn** (cheap-safe; a returned member is first resumed per **Returned-without-witness**); never fall back to a hint. Synthesizing, judging convergence for, or recording ledger content for a member whose witness was not observed is **fabrication and is forbidden**.
- **Universal witness.** This is not limited to "discussion rounds" — **every** member resume whose output the lead consumes is a witness target. This includes `design`'s Step-4 fidelity pass (`{role-slug}.fidelity.md`), the Step-5 walkthrough team, the Step-6 refinement team (each fresh team in its own directory from a fresh run of the `## Spawn` command), `design`'s Step-7 Class C coherence pass (`{role-slug}.coherence.md`), and `design-audit`'s reader fan-out (`{role-slug}.fanout.md`). Only phases that are **entirely lead-LOCAL** are exempt, and the exemption must be explicit.

## Teardown & abort

Teardown is **automatic** — a returned task has self-terminated, so there is nothing to shut down (no `shutdown_request`, no `TeamDelete`, no `ps aux`). **Abort** = `TaskStop` on a _running_ `agentId`. Witness-directory cleanup and the per-row terminal strip (`scratchDir`, `outputFile`, `stallMark`, `witnessNonce` — **not** `epoch`) are in `team-cleanup.md`.

## Escalation (failure phenotypes)

Two cases (counters) plus one routing rule:

- **Case 1 — Thin-return stall** (counter): a task publishes an empty or substanceless witness. 1st → re-scope + resume once (hard prompt: "no empty witness — deliver the result or name a concrete blocker in one line"); 2nd consecutive → `AskUserQuestion` (proceed without this member / re-scope once more / abort). If excluded, mark the exclusion in the synthesized document's metadata and set that member's ledger row `state=aborted` — removing it from the dispatch-completeness roster and the `state=running` residual scan, the same terminal disposition Case-2 option-③ gives a partial-closed member (no `TaskStop` is needed: a thin-return member has already self-terminated). The `aborted` stamp governs roster membership; the document mark is the reader-facing exclusion record. Setting `aborted` does not erase the member's already-converged contribution, which lives in the document body.
- **Case 2 — Never-returns** (binary, not a counter): the death verdict of the reconcile ladder holds (a WEDGED verdict — available + byte-stable `output_file` — sustained to `reentryCount ≥ K` with the FINAL adjacent `witness_present` re-check still absent). Death is the WEDGED arm only; the other never-returns sub-modes route to a **K-independent debounced-ask** (never a kill): an `UNAVAILABLE` `output_file` (`unavailStreak ≥ 2` for a vanished path / `emptyStreak ≥ M` for a never-populated `∅`), and **babbling** — a member that is _available but never witnessing_ (every re-entry reads ALIVE because the transcript keeps growing, yet no witness is ever published) at `growthStreak ≥ G (=5)`. All three K-independent triggers (`unavailStreak ≥ 2` / `emptyStreak ≥ M` / `growthStreak ≥ G`) are durable, so they accumulate across compaction. The recovery for the WEDGED arm is `TaskStop` + same-round respawn; every sub-mode (a death-respawn that also dies, or any ask trigger) routes to the single 4-option `AskUserQuestion` menu in the reconcile ladder above (no separate menu is defined here).
- **Case 3 — Non-conforming witness** (routing rule, not a bound): the witness is present but off-contract (spec-violating / malformed content above the sentinel). It is not caught by a counter (the witness published) — cross-review and the Step-4 fidelity pass catch it. The lead re-assigns once; a recurrence feeds the Case 1 counter.

"Reasonable bound" for never-returns is not a single death predicate but the union of **four durable escalation paths** that together cover the verdict space — no wall-clock constant (a long-running scope, e.g. a deep audit, is legitimate): WEDGED → `reentryCount ≥ K` → death + respawn; vanished → `unavailStreak ≥ 2` → ask; `∅` → `emptyStreak ≥ M` → ask; **available-but-never-witnessing (babbling) → `growthStreak ≥ G` → ask**. All four counters are durable, so the member cannot park indefinitely under any single sustained verdict; a trajectory that alternates verdicts to stay below every threshold is bounded only by the harness per-agent lifetime and is accepted as negligible. The `growthStreak ≥ G` ask may fire on a productive-but-slow member; that is the intended fail-toward-ask tradeoff, since its menu includes ② keep-waiting, not a kill. Surface to the user (`AskUserQuestion`) only on a Case-1/Case-2 threshold or explicit user instruction — never on wall-clock time, lead confidence, or lead opinion alone.

## Role↔agentId ledger v3

The model is roster-less, so an in-context list of agentIds evaporates on compaction with no fallback. Persist a **durable ledger** co-located with each skill's existing artifact:

- **Every skill that carries its ledger in its own output document**: an HTML-comment block at the top of the output document (right after the H1, before the first `##`): `<!-- cc-design-ledger v3 … -->`. A visible `##` section is forbidden (it would collide with the walkthrough / implement / audit heading parsers and would leak opaque agentIds into the user-facing doc). The doc is created as an **early stub** (title + ledger block) at spawn time, before Step-4 save.
- **design-analyze**: a `"ledger"` key in the existing `.{slug}.work.json` (already machine-only) holding the same per-row data.

Each ledger entry is **behavior-bearing**:

```
agentId | state | round/phase | role/scope (1 line) | thinReturns | last-return summary | scratchDir | outputFile | stallMark | epoch | witnessNonce
```

where `state ∈ {running, done, aborted}`, `outputFile` is the member's harness `output_file` path (the liveness-signal source), and `stallMark = {reentryCount, lastBytes, lastBytesPathTag, unavailStreak, emptyStreak, growthStreak}` is the durable death-predicate state (see the reconcile ladder); `epoch` is the monotone team-generation index (current team = `max(epoch)` over non-aborted rows), and `witnessNonce` is the per-(member, round/phase) `{WITNESS_NONCE}` — **written by the lead into the row at each primary fan-out (initial spawn, round-advance, convergence resume) and reused verbatim by a recovery dispatch whose dispatch round/phase equals the recorded nonce's round-tag; a recovery dispatch into a new round/phase (e.g. a round-advance-dropped member's self-heal, recorded tag `(P-1)≠P`) mints a fresh nonce per the mint-vs-reuse disk predicate** — so the self-heal-consume branch's `witness_present` conjunct-3 stays evaluable across the compaction that drops the in-context nonce. Update it on every state change.

- **Immediate record.** `scratchDir`, the team's `epoch`, and the member's round-1 `witnessNonce` are written into the row at spawn time with the **same immediacy as `agentId`** (the recording window is the existing agentId-recording window — no new exposure window). On each subsequent primary fan-out (round-advance / convergence) the lead writes that round's fresh `witnessNonce` **before** issuing the resume; a recovery dispatch reuses the recorded value iff its dispatch round/phase equals the recorded nonce's round-tag, else mints (per the mint-vs-reuse disk predicate).
- **Derive-from-ledger, never re-`mktemp`.** Every resume and every post-compaction re-entry derives `WITNESS_DIR` from the row's `scratchDir`. Re-running `mktemp` would create an empty directory, orphan the in-progress witness, and reopen the fabrication hole. **Re-read the ledger from disk on entering any phase that resumes a task** (Step-4 fidelity pass, Step-5, Step-6, Step-7 coherence pass) — do not trust in-context copies. **Fail closed via `AskUserQuestion`** (never silent-skip) on any of:
    - the ledger block is missing or unparseable;
    - a `state=running` row has no `scratchDir`, or one whose path is not on disk;
    - the non-aborted rows are in **partial** `epoch` presence (mode (iii) of the roster's 3-way precondition — uniform `epoch` absence is **not** a fail-close; it routes to the epoch-agnostic roster of mode (ii));
    - a `state=running` row has no `witnessNonce` (partial or uniform alike: without it `witness_present` conjunct-3 cannot be re-derived, and unlike `epoch` the nonce has no uniform-absence exemption).

    A residual `state=running` row is also the leftover-detection signal.
- **Transient.** `scratchDir`, `outputFile`, and `stallMark` are meaningful **only** while a row is `state=running` (the compaction / workflow-abort recovery window). On **normal workflow completion** all three are **per-row stripped from every terminal row** (`done` and `aborted` alike), and that strip runs **after** the directory `rm -rf`, never merely alongside it (the order and its reason are owned by `team-cleanup.md`). The cleanup axis is the **workflow result**: preservation applies only to a **workflow-level abort**; an individual `aborted` row is still stripped if the workflow completes normally. A committed document from a normally-completed workflow therefore carries these three on **0** rows. (`witnessNonce` joins these three per the classification below; **`epoch` does NOT**.)
- **Durability vs terminal-strip are orthogonal axes.** A field is **durable** (compaction-surviving mid-workflow) iff its loss would make a decision _unbounded_ (infinite park / resurrection) or _unsafe_ (false-kill / fabrication) — so the whole `stallMark` is durable. A field is **terminal-stripped** iff retaining it in a committed document would leak (scratch path / session path / stale counter). `stallMark` is **both**.
- **`epoch` vs `witnessNonce` — different axes, deliberately unbundled.** Both are **durable while any row is `state=running`**. **`witnessNonce` is terminal-stripped** on normal workflow completion: it is re-issued at every primary fan-out and is a random token that would leak. **`epoch` is NOT stripped, on any path**: it is the sole durable source for a later `max(disk epoch, 0) + 1` and for the roster's `max(epoch)` scoping, it leaks nothing, and stripping it makes every re-entry into a completed ledger a mode-(iii) partial-`epoch` fail-close.

## Per-skill parameter seam

The contract above is defined **once** here — including the full ledger v3 row schema, of which `outputFile` and `stallMark` are **protocol-owned columns**, not per-skill parameters. Each SKILL.md supplies only its **parameters**: the scratch-dir slug handed to the `## Spawn` command (the command itself, its root and its name form are fixed under **Spawn** above, so a SKILL.md supplies neither), which rounds / phases are witnessed (e.g. `design` marks its fidelity / walkthrough / refinement / coherence phases witnessed; `design-audit` marks its single `fanout` phase witnessed; `design-analyze` carries the ledger in its `work.json` `"ledger"` rows), whether the skill opts in to the **progress checkpoint** defined below, and — for a skill bound by `_common/team-model-tier.md` — the spawn `model` that file's table assigns to each seat. The document-ledger skills **point to this row schema** rather than re-typing the column list. No skill inlines or paraphrases the contract.

### Parameter — progress checkpoint (opt-in)

A member holds its findings long before its first witness lands; the lead structurally cannot. So the **member** writes a running checkpoint of what it has so far, and the sole-authorship anchor is unchanged — the lead never writes a member's witness and never writes a member's checkpoint either.

**Opted in by `review`, `review-unattended` and `review-lite` only.** A member of a skill that has not opted in writes no checkpoint. The clause below is therefore **not** part of the task-assignment header block: every skill that spawns a team embeds that header verbatim, so a clause in its body would start checkpoint writing in stage kinds this parameter has neither measured nor costed — `design-audit`'s independent-replicate fan-out above all, a single round where the "ride along on a call you were making anyway" cadence does not hold. An opted-in SKILL.md appends the clause **after** the header instead.

- **Path** — a `partial/` subdirectory beside the witnesses: `${scratchDir}/partial/{role-slug}.{round/phase}.md`. It sits outside the witness key namespace. **Creating that directory is the writer's duty and therefore rides in the clause itself**, not in the lead's spawn step. Two reasons, and either alone is sufficient: rename atomicity forces the temp into the same directory as the target, so a missing directory fails at temp creation rather than at publish and the `mkdir -p` has to precede the temp; and a `review` Step-6 follow-up team creates its own nested scratch dir, so a one-shot creation on the lead side would leave that team writing into a directory nobody made.
- **Sentinel** — the last line is `<!-- cc-partial: {role-slug} {round/phase} progress {WITNESS_NONCE} seq=<n> -->`. It differs from the witness sentinel in **two tokens**: the comment key (`cc-witness` → `cc-partial`) and the state verb (`complete` → `progress`).
- **Publish** — write the whole file to a sibling temp and publish with plain `mv`. **`mv -n` is not used here**; the distinction and its reason are owned by `_common/sidecar.md` (「**Plain `mv`, never `mv -n`.**」) and are not restated in this file.
- **Cadence — round 1 only.** Once the first finding clears the member's own confirmation bar (a dedicated turn is allowed for that one), then refreshed on Bash calls the member was making anyway. `seq` counts from 1. **In round 2 and later a member writes no checkpoint at all**, for the reason below; the path keeps its `{round/phase}` token regardless, so the file layout and every reader of it are unchanged.

**Why round 1 and no later round.** The cost of this parameter is charged per member-**round** — one dedicated turn each time — while the loss it converts from total to partial is, by its own definition, confined to round 1: the event is a crash *before the member's first witness lands*, and that witness lands at the end of round 1. From round 2 on the member already has a completed witness on disk, so a crash costs one round's increment rather than the stage. Charging every round for a benefit that only round 1 can realise was a scope mismatch rather than a deliberate trade, and the measurement that surfaced it also priced it: across 1,402 reviewer-rounds the median round-1 member spends 33.5 grounding turns against 13 in round 2 and 8 in round 3, so the same one-turn charge is 2.6x and 4.2x heavier exactly where it buys least. Restricting to round 1 keeps the parameter inside the span its own cost model was written for.

**What this gives up, stated rather than implied.** Two things, and neither is nil. First, a crash in round 2 or later now recovers that member's round-1 witness and nothing of the round in progress — measured at a median 24.4% of the member's total turns. Second, and less obvious: a round-2 checkpoint used to be one of **two independent ways** the recovery arm's interlock suppresses the termination-predicate line, the other being the ledger's `round/phase` column reading higher than the role's resolution round. That column is documented above as a conservative under-claim that may lag a live resume, so in the lag window the round-2 checkpoint was the only suppressor left. The window is one atomic ledger-row Edit wide and a member needs several turns to reach a confirmed finding, so a round-2 checkpoint almost never landed inside it — but "almost never" is not "never", and after this restriction nothing covers that window. The hole itself is not new here and is already pinned as a disclosure by `scripts/lint-recovery-interlock-pins.sh`; what changes is that it is no longer partly covered. Closing it belongs to the flip's ordering, not to this parameter.
- **Nothing new is minted** — no phase token, no nonce (the witness nonce is reused verbatim), no ledger column, and no new substitution parameter: the path is derived from `{WITNESS_PATH}`, and the clause substitutes only the four the header already substitutes.

**Nobody reads a checkpoint in a live run.** If the lead could read one, the reconcile ladder's fail-closed gates would acquire a textually-available soft fallback at exactly the moment pressure is highest — and a checkpoint is by definition unconverged and un-cross-reviewed, which is precisely the material Round 2 exists to filter. This rule binds the **lead**, so it lives here and is deliberately absent from the clause injected into members.

`witness_present` fails against checkpoint bytes at **two conjuncts independently** — the path differs (conjunct 1) and the last line's two tokens differ (conjunct 2) — so it is fail-closed against a path slip and a content slip alike.

Clause text, appended verbatim after the task-assignment header by an opted-in SKILL.md:

```
**Progress checkpoint (MUST — round 1 only)**: **this applies in round 1 and in no later round; from round 2 on, write no checkpoint.** In round 1, at your first confirmed finding (a dedicated turn is fine for it), `mkdir -p "$(dirname {WITNESS_PATH})/partial"`, then write your ranked findings so far whole to a sibling temp in it and publish with plain `mv` (never `mv -n`) at `$(dirname {WITNESS_PATH})/partial/{role-slug}.{round/phase}.md`, last line exactly `<!-- cc-partial: {role-slug} {round/phase} progress {WITNESS_NONCE} seq=<n> -->`, `seq` from 1. Refresh on Bash calls you were already making.
```
