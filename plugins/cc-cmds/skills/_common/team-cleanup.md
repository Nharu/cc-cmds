# Team Cleanup (Shared Procedure)

In the nameless-background-task model (`agent-team-protocol.md`), a member **self-terminates the moment it returns** — there is nothing to shut down. The old `shutdown_request` → `TeamDelete` → `ps aux` procedure is gone.

**Which arms apply turns on one question: is the workflow finished?** A caller invoking this file at a **phase boundary inside a running workflow** takes the mid-workflow arm; only a caller at the **end** of the workflow takes the completion arm. Each arm is individually idempotent — re-running the same arm is a no-op — but **the arms are not interchangeable**, and an unqualified instruction to *"Read and apply `team-cleanup.md`"* is not a licence to take the completion arm early. Taking it early destroys state a later phase still needs, and the loss is not recoverable. Every calling skill states which arm its call site takes.

- **Member processes, at any boundary** → **no-op on normal return.** Every member that returned has already self-terminated. There is no team directory and no orphan process.
- **Abort** → call `TaskStop` on every `agentId` whose ledger `state` is still `running` (a wedged/never-returned task per Case 2). `TaskStop` on an already-returned task is a harmless no-op.
- **Ledger hygiene, at any boundary** → update the ledger so no `state=running` row survives the phase that just ended: set returned members to `done` and any `TaskStop`-ed member to `aborted`. A residual `state=running` row is the only leftover signal, so leaving one stale would produce a false leftover detection.
- **Mid-workflow phase boundary → RETAIN every transient field and every witness directory.** Where phases remain — most sharply where a later phase **resumes this same team** — perform the two checks above and **stop**: no witness-directory `rm -rf`, and no per-row strip of `scratchDir`, `outputFile`, `stallMark` or `witnessNonce`. A resumed phase is witnessed too, and the protocol requires its witness path to be derived from the row's recorded `scratchDir` rather than re-`mktemp`ed, so a mid-workflow strip of that field leaves the later phase with nothing to resume from. Where the phase that just ended still has an unpublished witness, removing the directory destroys it outright — and a witness is the sole anchor of the anti-fabrication guarantee, so its loss is exactly the path by which a lead ends up synthesizing output it never observed. **A caller that cannot tell whether the workflow is finished takes this arm**: its worst outcome is cleanup deferred to the end, and the other arm's worst outcome is unrecoverable.
- **Workflow completion → the transient fields and the witness dirs go.** On **normal workflow completion**, `rm -rf` each team's witness directory (path-guarded to the recorded `cc-team-witness-<slug>` `scratchDir`, never a bare or computed path) **and** per-row strip `scratchDir`, `outputFile`, `stallMark`, and `witnessNonce` from **every** terminal ledger row (`done` and `aborted` alike — including a member left `aborted` by a Case-2 partial synthesis). Stripping these four keeps the committed document free of the TMPDIR-hash / session-path / stale-counter / random-nonce leak (per the ledger v3 transient-field classification). **`epoch` is never terminal-stripped** — it is the only durable source the next `max(disk epoch, 0) + 1` re-derivation and the roster's `max(epoch)` scoping can read, and an integer generation index leaks nothing (no TMPDIR hash, no session path, no random token). Stripping it made **every re-entry into a completed ledger** produce partial-`epoch` presence — old rows without it, new rows with it — which the roster's 3-way precondition classifies as mode (iii) and fail-closes at the first pre-wait gate, every time. On a **workflow-level abort**, the witness directories and the rows' `scratchDir`, `outputFile`, `stallMark`, and `witnessNonce` fields are **retained** for audit/recovery (`epoch` is never terminal-stripped on any path, so it has no abort-specific arm). **The scoping to *terminal* strip is deliberate**: it forbids this procedure from removing `epoch` when it retires a row, and it does not forbid the bounded clear the protocol's re-convened-team re-stamp performs, which is always followed by a write inside the same procedure. The cleanup axis is the workflow result, not the per-row state. The witness dir is out-of-tree (`${TMPDIR:-/tmp}`), so neither retaining nor removing it touches the two-command boundary gate.

NEVER use `rm -rf` or `kill` on agent processes. The witness-dir `rm -rf` above is the sole exception and is path-guarded to the recorded `scratchDir`.
