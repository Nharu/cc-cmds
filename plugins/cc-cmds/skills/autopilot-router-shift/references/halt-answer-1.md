#### Handing on a person's answer to a halt

A stage that reached a question only a person can answer wrote a halt record and stopped; the seat asked the person and wrote the answer as a `중단 답` row. The snapshot's `answered_halts[]` lists each answer no stage has taken up yet — `segment` (the segment id, or the step id of a run-scope step — the design, the audit or the split), `record` (the halt record's path), `skill`, `option` (verbatim), `answered_by` (`사람`, `좌석` when the seat answered with the record's own `**추천**` and no person, or `교대` for the pre-adopted answer below), `attachment` (a file under the run's `halt/` holding what the person supplied beyond the option — or, on a seat answer, the quotes the recommendation rests on — or the empty string), `origin_run` (the earlier run whose seat took the answer, when an adopted segment's planning act or a re-kickoff's first dispatch of a run-scope step brought it here — see 「Planning the segments」 and item 3 below — or the empty string), `route` (the gate's routing id for the answer, one of `재부착`, `감사-재수렴`, `골격급-재수렴`, `구속-재수렴`, `교대-정지`, `빈-대상` and `설계-재수렴`, or the empty string), `route_refusal` (when `route` is empty and the record exists, the gate's reason it has no path to carry the answer out), `line` (the row's ledger line, whose `근거` holds the person's words) and `state` (`이월` when a carry act of this run found no account with room before the deadline and kept the answer in an `이월` row, and `열림` otherwise). **An element reading `state` `이월` is not carried again in this run** — the gate refuses it with exit 3 — and it is not a question for the seat: it waits for the next run, which takes it up with the carry act. When such elements are all that is left, end with `사유=이월`. The gate computes `route` with the same judgment `halt-answer` applied when the answer was written, so you do not derive it again. The snapshot's `returned_halts[]` lists the answers item 8 handed back to a person — `segment`, `record`, `option`, `answered_by`, `answer_line`, `reason` and `line` (the `blocked` row's ledger line) — and they are not in `answered_halts[]`: such a record waits for a person's new answer, which arrives as a new element. **Any other element of `answered_halts[]` is this loop's to route, not a park and not a reason to end the shift.** Take it before 「Continuing a stage that ended its turn in prose」 and before any fresh dispatch on the same key. Every read here is a gate call on the terms 「Recovering a review stage that crashed」 states. The element leaves the list by itself once a `stage-result` row of its key lands on a later line, so dispatch on it once.

**A binding-tier stop the manifest pre-adopted is answered here, not at the seat.** When a segment's last `stage-result` row reads `종류=implement` with `종단 부류=의도된 park`, its halt record (`"$CC_PIPELINE_RUN_DIR/halt/<id>#<실행 버전>.md"`, read through the gate) has `**스킬**: implement-unattended`, its step text before the first ` — ` contains `CFI-U3 BT-STOP`, it lists the option `` `재수렴` ``, no `중단 답` row names it yet, and the manifest's `## 인가` carries a `자동 채택` row with `판단 부류=구속-이탈`, write the answer yourself instead of ending with `사유=중단`:

```
gate.sh act --manifest <매니페스트> --kind halt-answer --target <alias> --segment <id> \
  --cutpoint <token> --surface 읽기 --snapshot-digest <H> \
  -- '중단 기록=<그 기록의 절대 경로>' '선택지=재수렴' '근거=구속-이탈 자동 채택 — 매니페스트가 킥오프에서 미리 정한 답'
```

The gate admits a shift on exactly these conditions, stamps the row `답한 주체=교대` (do not pass that field — the gate refuses a shift that does), and bounds it by the `자동 채택` row's `상한`: it counts the key's automatic `재수렴` answers — the seat's and the shift's, never a person's — against that value, `없음` admitting any number, and it refuses a second automatic `재수렴` to a record whose earlier `재수렴` a re-convergence already took up. Like every writer's answer, it is also refused when the gate finds no path to carry it out — stderr `라우팅 불가 — <reason>`, here a segment already terminal. A refusal is exit 3, and then the stop goes to a person as before: the stage's own record is already the one the seat asks, so it needs no `shift-halt` — dispatch nothing on the segment, route the others, and when nothing is left end with `사유=중단`, naming the record in `막힌 지점`. Exit 3 for any other reason means the same. On exit 0 read the snapshot again: the answer is now in `answered_halts[]` and item 5 below routes it. Without the `자동 채택` row this paragraph does not apply and the stop goes to a person.

1. **Nothing is running on it.** The key is in none of `live_stages[]`, `orphan_stages[]` and `waiting_stages[]`.
2. **Which path is the element's `route`.** The gate decided it, for every writer, before it wrote the answer; do not read the record to decide it again.

   **Release a run-scope routing block first.** A person's new answer to a record item 8 handed back arrives here as a new element with a `route`, not at item 8. When the snapshot's `blocked[]` holds an element whose `사유` begins `중단 답 라우팅 — <the last component of this element's record> — ` and whose anchor is a run-scope step id (the design, the audit or the split), write the release row of item 8's run-scope bullet — `스코프=run 원인=해소` with that same `사유` — before routing the element below; the dispatch items 3–7 and 9 take does not release it. With a segment anchor write no release row and route the element directly.

   | `route` | item |
   | --- | --- |
   | `재부착` | 3 |
   | `감사-재수렴` | 4 |
   | `구속-재수렴` | 5 |
   | `교대-정지` | 6 |
   | `빈-대상` | 7 |
   | `설계-재수렴` | 9 |
   | `골격급-재수렴` | 10 |

   **A re-audit's `Step 7 / 골격급 재발` record takes one of two routes**, the record's `**스킬**` being `design-audit-unattended` and its `**스텝**` beginning `Step 7 / 골격급 재발`: answered `재수렴`, the gate gives `골격급-재수렴` and item 10 dispatches the re-convergence; answered `미해결 이슈로 두고 계속`, it gives `재부착` and item 3 hands the answer back to the audit session, which records the remaining items and finishes. An element whose `route_refusal` is not empty — its path closed after the answer was written — goes to item 8. **A design stage's `/ ladder-unsettled` record answered `골격 재검토` takes one of two routes.** The gate gives `설계-재수렴` when the key's last `stage-result` row reads `종류=design` with `종단 부류=정상 완료` — the document was already frozen on an earlier `잔여로 두고 동결` answer to the same record. Otherwise it gives `재부착`: the re-attached design writes the review marker and freezes, and item 5 of 「Dispatching the design stage」 then sends the run to item 9.

   **A `좌석 실행` stop is re-attached directly.** For a `route` of `재부착`, read the record's step line: `grep -n '^\*\*스텝\*\*: ' <record>`. When the step begins with `Step 3 잔여 검증 좌석 실행` or `Step 3 게이트 도달 좌석 실행`, whoever answered and whatever the option, the halted session is the one that reads the answer — the seat's run of the record's commands or recipes, or what a person chose when the seat put the record to them: do not issue the carry act, which refuses an answer to such a record with exit 3 on its step alone — re-attach the halted session with item 3's `--resume` form directly, its sentence chosen by `option` and `answered_by` as item 3 says. Every other `재부착` answer goes to item 3.
3. **Settle the answer first when its record already fixed the outcome.** A re-convergence that stopped with its edit on disk and its verdict computed writes the option in the machine settlement grammar (`pipeline-sidecar.md`, the paragraph on settling a halted re-convergence): `` - `<label>` — 검사 sha256 <document>=<64 hex> → 종단 재설계 필요 `` or `… → 종단 불필요`. When the element's `skill` is `design-reconverge` and the record's line for the element's `option` begins `` - `<option>` — 검사 sha256 `` (`grep -nF` through the gate), issue the settle act before anything else on the key:

   ```
   gate.sh act --manifest <매니페스트> --kind halt-settle --target <alias> --segment <segment> \
     --cutpoint <token> --surface 읽기 --snapshot-digest <H> \
     --rationale '중단 답 줄 <line> 정산' \
     -- '중단 답 줄=<line>'
   ```

   `<segment>` is the element's `segment` verbatim — the segment id, or for a run-scope step the step id, never `-`: the answer's row names its key there, the gate matches the key against it, and it refuses `--segment -` before reading anything. Exit `0` → the gate wrote the re-convergence's `stage-result` row itself, carrying `정산=중단 답 줄 <line>` and the line's `재수렴 판정`, and that row took the answer up: no session runs, so carry nothing — go straight to the **After it ends** of item 4 (the key's earlier rows are an audit's) or item 5 (they are an implementation's), which read that row. Exit `3` → the gate found one of its checks unmet and wrote nothing; the answer is still open, so carry it below. Exit `4` is the stale digest every act meets: read the snapshot again and issue it once more. Any other exit — a refused argument (`2`) included — wrote no row either, so read it as `3` and carry the answer below. A record whose option line is not in that grammar is carried below without the settle act.

   **Otherwise carry the answer, and let the gate decide whether the halted session takes it.** The halted session may be bound to an account that has no room before the deadline while another has room now; the carry act asks for the bound session first and, when it is not granted, for a fresh one, and hands the answer to whichever starts as an answer card named by `CC_PIPELINE_HALT_ANSWER`. Keep the halted attempt's stage kind, target and `--segment` (`-` for a run-scope step), pass the element's `line`, and give the dispatch form the gate's re-entry table holds for the halt — never `--resume` beside it:

   ```
   gate.sh act --manifest <매니페스트> --kind skill --target <alias> --segment <id | -> \
     --cutpoint <token> --surface <token> --snapshot-digest <H> --carry-answer <line> \
     --rationale '중단 답 줄 <line>' \
     -- <스테이지 종류> -p "<새 파견 형식>"
   ```

   The table holds two halts. An audit's synthesis stop (`skill` `design-audit-unattended`, step text containing `CFI-3b`, any option but `adopt as a requirement`) is carried as `audit` with `-p "/cc-cmds:design-audit-unattended <스냅숏 design_doc>"`. A re-convergence's stop at its Step 3 (`skill` `design-reconverge`, step text beginning `Step 3`) is carried as `reconverge` with `-p "/cc-cmds:design-reconverge <문서> <범위>"` — `<문서>` the main-worktree absolute path the re-convergence dispatches already pass, and `<범위>` the value after `범위=` in the record's `**관측 상세**`, verbatim. The gate compares the frame byte for byte and checks the scope against the record and, for an `R<n>`, against a waiting carrier block. What the exit code says next:

   | Exit | What happened | What you do |
   | --- | --- | --- |
   | `0` | a session started with the answer — the halted one or a fresh one | wait on it as *Waiting on a stage* describes; its `stage-result` row takes the answer up |
   | `19` | the halt is not in the re-entry table, or its scope is not one the gate can check | re-attach the halted session with `--resume` as below. **This is the only exit that sends you there** |
   | `3` | the answer is not this dispatch's to carry — another item routes it, it is spent or carried over already, a later answer stands, the record changed, or the argv is wrong | write nothing on the key and end with `handoff 사유=중단` once nothing else is dispatchable, naming the record in `막힌 지점` |
   | `16` | the gate parked the carry before any session started. Read the snapshot again and take the element by its `line`: `state` `이월` → no account has room before the deadline, and the gate wrote an `이월` row keeping the answer for the next run; `state` `열림` → the gate parked it for another reason — a configuration park a person must fix, a `stage-wait` row it could not write, a new account's PARK that is not the deadline, a routing guard record that does not match, a stall threshold it could not read — and wrote no `이월` row | `이월`: when the run has no run-scope end row, end with `handoff 사유=이월` once nothing else is dispatchable; when it has one (the carry came after the deadline closed the run), end with `handoff 사유=종단`. `열림`: dispatch nothing on the key and do not carry the answer again in this shift; end with `handoff 사유=중단` once nothing else is dispatchable, naming the record and the park row's `사유` in `막힌 지점` — or, for the stall threshold, which writes no `blocked` row, the gate's `warn` line. The element stays `열림` in `answered_halts[]`, so a later shift carries it again: that is the carry a person wants once they have removed the park's cause, and until then it meets the same `16`. The gate's two guards on a `중단` hand-off — only carried-over answers left, a carried-over record named in `막힌 지점` — do not refuse it, because this answer is `열림`, not carried over |
   | `18` | the carry's cap — attempts that carried the answer died before a session three times, or one stopped again on the same question — and the gate wrote its `blocked` row | dispatch nothing on the key; end with `handoff 사유=중단` naming the record and the cap row's `사유` in `막힌 지점` — the seat reads the cap from that field, because the snapshot's `blocked[]` carries no act-scope row. The element stays in `answered_halts[]` for the person who reads that row, and it is not carried again in this run: the cap counts what is already on the ledger, so another carry only comes back `18` again, and the gate does not write the row twice |

   **An answer the earlier run carried over arrives through a refused first dispatch.** On a re-kickoff's follow-up run — the manifest's `이어받은 런` row names the earlier run — the first dispatch of a run-scope step (the design, the audit or the split) whose step the earlier run left with an answer an `이월` row names is not started: the gate copies that halt record under this run's `halt/`, writes the answer as this run's own `중단 답` row with `출처 런` and `출처 기록`, and refuses the dispatch with exit 3, naming the line in a `--carry-answer <line>` warning. That `3` is not the table's: write nothing on the key, read the snapshot again, and issue this item's carry act with that line — the element now in `answered_halts[]` with that `line` and, as `origin_run`, the run the person answered in — the earlier run, or the run before it when the earlier run had itself brought the answer in and carried it over again. Until the carry act takes it, every other dispatch on the key is refused the same way, so never retry the plain dispatch. Such an element — and an adopted segment's answer an `이월` row named — reads an empty `route_refusal` (`route` `재부착` for an answer that re-attaches), because the gate reads the halted attempt from that run's ledger; it still goes to this item's carry act, not to a `--resume` and not to item 8.

   **Re-attach with `--resume` only after exit 19, or for an answer to a `좌석 실행` stop item 2 sent here.** Take the key's last `stage-result` row and its `세션 id` as 「Re-attaching a cut stage」 items 2 and 3 read them; the id must not be `미상` and the attempt's stream must show the session started. Keep the halted attempt's stage kind, target and `--segment` (`-` for the design step):

   ```
   gate.sh act --manifest <매니페스트> --kind skill --target <alias> --segment <id | -> \
     --cutpoint <token> --surface <token> --snapshot-digest <H> --resume <세션 id> \
     --rationale '중단 답 줄 <line>' \
     -- <스테이지 종류> -p "중단 기록 <record> 의 질문에 사람이 \`<option>\` 을 골랐습니다. 사람이 덧붙인 말은 런 원장(환경 변수 CC_PIPELINE_LEDGER 가 가리키는 파일) <line> 번째 줄 \`중단 답\` 행의 \`근거\` 에 있습니다.[ 사람이 건넨 내용은 <attachment> 에 있으니 읽고 답의 일부로 쓰세요.] 그 선택지를 질문의 답으로 받아, 기록이 적은 스텝부터 이어서 진행하세요 — 처음부터 다시 하지 말고, 중단 전에 끝낸 스텝은 다시 하지 마세요."
   ```

   The prompt is that sentence with `<record>`, `<option>`, `<line>` and — only when the element's `attachment` is not empty, as the bracketed sentence without its brackets — `<attachment>` filled in, and nothing else. **Who chose is the element's `answered_by`**, and the sentence says it: for `좌석`, write `좌석이 기록의 추천 선택지 \`<option>\` 을 골랐습니다` in place of `사람이 \`<option>\` 을 골랐습니다`, `좌석이 적은 근거` in place of `사람이 덧붙인 말`, and `좌석이 건넨 내용` in place of `사람이 건넨 내용`; for `사람`, the sentence as shown. A stage told a person chose an option the seat took from its own record would weigh it as a person's decision. **A `좌석 실행` answer is the seat having run the record, not chosen from it**: when `option` is `좌석 실행` and `answered_by` is `좌석`, write `좌석이 기록의 좌석 실행을 마쳤습니다` in place of `사람이 \`<option>\` 을 골랐습니다`, `좌석이 적은 근거` in place of `사람이 덧붙인 말`, and `좌석이 건넨 실행 결과` in place of `사람이 건넨 내용` — the stage then reads the grades or the command results as its own skill says. Name the ledger by that phrase, never by its path: the stage has the variable already, and a `.md` path outside `halt/` in an implement or re-convergence prompt is read as its document argument and refused. An option such as "the person reports the measured values" is answered by what the person said, not by its label; a stage handed the label alone halts again asking for what the seat already holds. The gate accepts any session id on this stage's own `stage-result` rows, whatever their class, so a `정상 완료` or `의도된 park` row is no bar. When the stream does not show the session started, or the gate refuses the `--resume` act, go to item 8. A cone `blocked` row anchored on this segment is not closed by a row: it leaves `cone_blocks[]` once the segment's next `segment` row that is not `park` lands, so write nothing to release it.
