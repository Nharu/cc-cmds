# 프롬프트·모델 변경 블라인드 비교 규약

프롬프트나 모델을 바꾼 효과를 과금 실행으로 재는 실험이 따를 규칙이다. 이 디렉터리의 실험 하네스(`reader-model-pair-audit.sh`, `solo-audit-experiment.sh`)가 이 규약을 따르고, 새 하네스도 이 규약을 따른다.

## 1. 목적과 적용 대상

- 대상은 프롬프트·모델 변경의 효과를 과금 실행으로 비교하는 실험이다.
- 프롬프트나 모델을 바꿀 때마다 실험을 돌릴 의무는 없다. 실험을 할지는 바꾸는 사람이 정한다.
- 다만 변형을 과금 실행으로 비교하는 실험 하네스를 `scripts/` 아래에 새로 두거나 고칠 때는 아래 여섯 규칙을 모두 따르고, 하네스 머리말에 규칙별 대응 블록(10절)을 둔다. 각 하네스의 시험이 그 대응을 기계로 지킨다.

## 2. 용어

- **후보** — 재는 대상인 스테이지나 세션. 실험이 띄우는 운영 경로의 스테이지가 여기에 든다.
- **팔** — 비교하는 변형 하나. 예: 판독자 모델이 opus 인 쪽과 sonnet 인 쪽, 단독 설계와 팀 설계.
- **심판** — 후보의 산출물을 읽어 판정 입력을 내는 LLM 호출.
- **계수기** — 모델 없이 산출물을 세는 결정적 스크립트.
- **후보 노출면** — 후보가 읽을 수 있는 모든 것. 작업 트리의 절대 경로, 그 클론의 git 브랜치·이력, 런 매니페스트와 인가 기록의 문면, 환경 변수, 프롬프트, 넘겨받는 파일 이름이 여기에 든다.

## 3. 규칙 1 — 후보 노출면 중립

하네스가 지어 넣는 문자열에는 금지어와 팔 이름을 두지 않는다. 후보가 자기가 실험 안에 있다는 것이나 어느 팔인지를 알면, 재는 것은 운영 경로가 아니라 실험을 의식한 행동이 된다.

금지어의 정본은 아래 한 줄이다. 하네스는 이 줄의 값과 바이트로 같은 상수를 갖고, 하네스의 시험이 둘을 대조한다.

**금지어**: eval evaluation evaluate judge judging rubric grader grading benchmark experiment exp 실험 평가 심판 채점 루브릭

맞춤 방식:

- 영문 낱말은 대소문자를 가리지 않고, 낱말 경계로 맞춘다. 경계는 `[A-Za-z0-9_]` 밖의 문자 또는 문자열의 처음과 끝이다. `exp-base` 의 `exp` 는 걸리고, `design_tier_judged` 의 `judge` 는 걸리지 않는다.
- 한글 낱말은 부분 문자열로 맞춘다.
- 팔 이름도 같은 방식으로 맞춘다. 팔 이름 목록은 하네스마다 상수로 둔다.

검사 대상과 고칠 대상은 하네스가 짓는 문자열이다: 후보가 열리는 클론의 절대 경로, 런 매니페스트 `## 대상` 행의 별칭·원격 슬러그·베이스 브랜치, 매니페스트와 인가 기록의 확인·승인 문면, 하네스가 짓는 의도 문면, 실행 계획 JSON 의 자유 문면 필드, 종료 지점과 종료 절 문면, 하네스가 만드는 커밋의 메시지와 작성자. 하네스 이름, 실험 id, 짝·문서 번호, 팔 이름, 금지어를 뺀 운영 문면으로 쓴다.

검사하지 않는 것:

- 운영 경로가 원래 싣는 값은 처치의 일부다. 감사할 문서 경로, 원 런의 의도 문면, 인터뷰 기록 사본, `design_tier` 같은 열거 필드 값이 여기에 든다. 이것까지 검사하면 하네스가 재는 대상을 바꾸거나 정당한 표본을 거부한다.

하네스는 실행 전 검사 함수 하나를 갖는다. 런 파일을 쓴 직후, 첫 과금 호출 전에(드라이 런에서도) 위 문자열을 문서 경로 자리에 자리표시를 둔 채 금지어 상수와 팔 이름 상수로 검사하고, 걸리면 그 낱말과 자리를 적고 종료 코드 1 로 멈춘다. 이 문자열은 하네스가 전부 짓는 것이라 걸렸다는 것은 하네스 결함이고, 멈춰도 표본을 잃지 않는다.

하네스 전용 환경 변수(하네스 이름을 접두어로 단 변수)는 후보 프로세스에 넘기지 않는다. 하네스는 시작할 때 그 변수를 셸 변수로 읽은 뒤 해제한다.

**남는 노출.** 두 하네스가 재는 레포는 이 레포 자신이라, 실험 클론의 트리에 `scripts/` 의 하네스와 이 규약 파일이 보일 수 있다. 클론 트리를 바꾸면 재는 대상인 오늘의 운영 경로가 바뀌므로, 이 파일들은 지우지 않고 남는 노출로 둔다.

## 4. 규칙 2 — 심판 익명

- 심판에게 주는 라벨은 내용 해시에서 만든다. 팔 순서나 팔 이름에서 만들지 않는다.
- 하네스가 심판에게 주는 문면(프롬프트, 입력 머리, 파일 이름, 경로)은 팔 이름을 쓰지 않고, 비교되는 팔이 있다는 사실도 알리지 않는다.
- 입력 안의 절대 경로는 `<ROOT>` 로 바꾼다.
- 산출물 내용에 원래 있는 팔 단서는 지우지 않고, 심판 호출 전에 세어 공시한다. 하네스가 보태는 단서는 없애고, 내용에 원래 있는 단서는 드러낸다. 지우면 심판이 읽는 산출물이 후보가 쓴 것과 달라지고, 그 짝을 무효로 하면 예비 표본이 금방 바닥난다. 공시 기록은 판정에 들어가지 않는다.
- 심판 모델은 `--model` 로 명시해 고정하고, 한 실험의 모든 팔에 같은 모델을 쓴다. 후보와 같은 모델 계열도 허용한다. 편향을 막는 장치는 익명 라벨과 결정적 교차 검사다.
- 계수기는 팔 이름을 써도 된다.
- 사람이 판정을 채우는 파일은 라벨만 쓴다.

## 5. 규칙 3 — 준수는 트랜스크립트로 채점한다

- 후보가 정해진 사슬을 따랐는지(어떤 파일을 읽었는지, 어떤 단계를 밟았는지) 재는 지표는 후보 세션의 stream-json 기록에서 도구 호출을 읽어 센다. `Read` 의 `file_path`, `Bash` 의 명령, `Agent`·`Skill` 호출이 그 근거다.
- 후보가 스스로 쓴 「읽었다」·「했다」 문면은 지표가 되지 않는다.
- 후보가 스스로 적은 과정 값(예: 감사 공시 블록의 리뷰어 수)은 보고서에 보여 줄 수는 있어도 판정식에 넣지 않는다.

## 6. 규칙 4 — 판정 규칙 사전 고정

- 임계 상수와 판정 순서는 첫 과금 호출 전에 상수와 골든 시험으로 고정한다. 한 실험 id 안에서는 바꾸지 않는다.
- 심판 프롬프트의 분류 기준 문면도 이 규칙의 대상이다. 규칙 2 를 맞추려고 팔 단서 문장을 빼는 것은 분류 기준을 바꾸지 않으므로 대상이 아니다.
- 고정한 판정 규칙을 바꿔도 되는 경우는 다음 셋뿐이다.
    - (가) 이 규약의 다른 규칙이 요구하는 판정 항이 그 규칙에 없을 때.
    - (나) 실험 결과가 아니라 시험이 규칙의 결함을 드러냈을 때.
    - (다) 재는 양 자체가 바뀌어 옛 규칙이 그 양을 읽지 못할 때.
- 결과를 보고 임계값을 고르는 것은 셋 어디에도 들지 않는다.
- 바꿀 때는 새 실험 id 의 첫 과금 호출 전에, 상수와 골든 기대값을 같은 커밋에서 바꾼다. 지난 판정은 옛 규칙으로 낸 것으로 그대로 둔다.

## 7. 규칙 5 — 노이즈 측정

- 팔을 비교하는 판정은 한 팔을 같은 입력으로 두 번 돌린 차이(노이즈)를 재고, 그 몇 배 안의 차이는 판정하지 않는 항을 갖는다.
- 이 규약보다 먼저 고정된 판정 규칙에 이 항이 없으면 대응표(9절)에 「기록된 차이」로 적고, 그 하네스로 새 실험을 열기 전에 규칙 4 의 절차로 넣는다. 이 경우는 규칙 4 의 (가)에 든다.

## 8. 규칙 6 — 예산 상한

- 과금될 수 있는 호출을 시작하는 하네스 호출은 `--budget-usd` 를 기본값 없이 요구한다.
- 과금 단계마다 그 단계가 상한을 넘을지 먼저 검사하고, 넘으면 종료 코드 4 로 멈춘다. 멈출 때는 끝나지 않은 표본을 무효로 적고 판정을 쓴다. 같은 명령을 더 큰 상한으로 다시 부르면 이어서 돈다.
- 과금 실험은 사람이 보지 않는 동안 도는 것이 보통이라, 상한 없는 실행이 쓴 비용은 되돌릴 수 없다.

## 9. 기존 하네스 대응표

이 규약을 넣은 변경 뒤의 상태다.

| 규칙 | `reader-model-pair-audit.sh` | `solo-audit-experiment.sh` |
| --- | --- | --- |
| 1 후보 노출면 | 고침 — 클론을 중립 작업 공간 뿌리 아래 무작위 이름으로 옮기고, 별칭 `work`·원격 슬러그 `local/work`·베이스 브랜치 `base` 로 바꾸고, 지어 넣는 문면을 운영 문면으로 바꾸고, 실행 전 검사와 하네스 전용 환경 변수 해제를 넣었다 | 고침 — 같은 내용 |
| 2 심판 익명 | 해당 없음 — 심판 없이 계수기(`reader-model-compare.sh`)만 판정한다 | 고침 — 분류 프롬프트에서 팔이 있다는 사실을 알리는 두 문장을 빼고, 분류 모델을 `opus` 로 고정하고, 심판 입력의 팔 단서 낱말을 세어 `classify/leak.tsv` 에 공시한다 |
| 3 준수 채점 | 해당 없음 — 사슬 준수를 재지 않는다. 후보가 적은 리뷰어 수는 판정식에 없다 | 해당 없음 — 사슬 준수를 재지 않는다. 후보가 적은 리뷰어 수는 교란 표에만 있다 |
| 4 판정 규칙 고정 | 충족 — 상수와 골든 시험으로 고정돼 있다 | 충족 — 상수와 골든 시험으로 고정돼 있다 |
| 5 노이즈 | 충족 — opus 두 번 실행의 변동 폭(W) 항이 있다 | 기록된 차이 — 노이즈 항이 없다. 이 하네스로 새 실험을 열기 전에 규칙 4 의 절차로 넣는다 |
| 6 예산 상한 | 충족 | 충족 |

지난 실험 20261024-5104680e(`solo-audit-experiment.sh`)의 분류는 팔 단서 문장이 든 분류 프롬프트로 냈다. 그 결과는 다시 내지 않는다.

두 하네스의 클론 경로·대상 별칭·베이스 브랜치 이름이 이 변경에서 바뀌었으므로, 이 변경 전 하네스로 열어 둔 실험 상태는 새 하네스로 재개하지 않는다.

## 10. 새 하네스 점검 목록

- [ ] 금지어 상수가 위 `**금지어**:` 줄의 값과 바이트로 같고, 시험이 둘을 대조한다.
- [ ] 팔 이름 상수가 있다.
- [ ] 후보가 열리는 클론·작업 트리의 절대 경로, git 브랜치 이름, 런 파일 문면, 커밋 메시지·작성자에 금지어와 팔 이름이 없다. 팔과 경로의 대응은 하네스 상태 파일에만 적는다.
- [ ] 첫 과금 호출 전(드라이 런 포함)에 실행 전 검사가 돌고, 걸리면 낱말과 자리를 적고 종료 코드 1 로 멈춘다. 시험이 걸리는 갈래를 하나 갖는다.
- [ ] 하네스 전용 환경 변수를 시작에서 읽은 뒤 해제해 후보 프로세스에 넘기지 않는다. 시험이 스텁 쪽에서 그 변수가 없음을 확인한다.
- [ ] 클론을 지우는 자리는 상태에 적힌 경로만, 그 경로가 작업 공간 뿌리나 상태 뿌리 아래일 때만 지운다.
- [ ] 심판 라벨은 내용 해시에서 만들고, 심판에게 주는 문면에 팔 이름과 팔이 있다는 사실이 없다.
- [ ] 심판 입력의 절대 경로를 `<ROOT>` 로 바꾼다.
- [ ] 심판 입력에 원래 있는 팔 단서를 세어 공시하고, 판정에는 넣지 않는다.
- [ ] 심판 모델을 `--model` 로 명시하고 모든 팔에 같게 쓴다.
- [ ] 준수 지표를 재면 트랜스크립트의 도구 호출로 센다. 후보가 적은 과정 값은 판정식에 넣지 않는다.
- [ ] 판정 상수와 판정 순서가 골든 시험으로 고정돼 있다.
- [ ] 판정에 노이즈 항이 있거나, 없으면 대응 블록에 기록된 차이로 적었다.
- [ ] 과금 호출이 `--budget-usd` 를 기본값 없이 요구하고, 단계마다 사전 검사 후 종료 코드 4 로 멈춘다.
- [ ] 머리말에 아래 꼴의 대응 블록이 있다.

머리말 대응 블록의 꼴(하네스 머리말 주석의 말씨에 맞춘 영문). 첫 줄은 시험이 그대로 찾는다.

```
# Protocol: scripts/prompt-change-protocol.md
#   1 candidate surface  — <met | changed: …>
#   2 blind judge        — <…>
#   3 compliance scoring — <not applicable: …>
#   4 fixed rule         — <…>
#   5 noise              — <met | recorded gap: …>
#   6 budget             — <…>
```
