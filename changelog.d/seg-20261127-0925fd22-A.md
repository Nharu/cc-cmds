등급: patch

연결 끊김이나 API 서버 오류(5xx·529)로 죽은 스테이지가 사람을 기다리지 않고 같은 런 안에서 같은 세션으로 다시 붙어 이어 갑니다. 문서를 저장한 뒤 연결이 끊긴 설계 스테이지는 지금까지 재부착도 재파견도 되지 않아 런이 멈췄고, API 500 으로 끝난 크래시는 일시 원인이 아닌 것으로 기록되었습니다.

### Fixed

- **일시 원인 크래시의 재부착** — 라우터 교대와 리드 사본의 재부착 규칙이 `종단 부류=크래시` 이고 `일시 원인=예` 인 행을 스테이지 종류에 상관없이 재부착 대상으로 받습니다. 연결 복귀의 근거는 끊긴 행을 읽고 재부착을 내는 교대 자신의 턴이며 따로 탐침하지 않고, 기존 재부착 3회 상한을 함께 씁니다. 이어 가기 프롬프트는 한 벌을 유지하고 원인 문구만 연결 끊김과 서버 오류까지 넓혔습니다.
- **리뷰 스테이지의 재부착** — 리뷰 스테이지를 재부착할 때는 이어 가기 문장 끝에 직전 리뷰 파견의 `--report-path` 를 덧붙이고 그 파견의 `계기` 를 `--trigger` 로 싣습니다. 게이트가 리뷰 재개에도 리포트 경로와 계기를 요구해 고정 문장만으로는 늘 거절되었고, 그 거절이 리뷰 크래시 복구까지 막았습니다. 계기 거절 뒤 한 번 다시 선언해도 거절되면 재부착을 접고 리뷰 크래시 복구로 넘어갑니다.
- **서버 오류의 일시 원인 판정** — `stage_transient_exit` 가 종단 객체의 `api_error_status` 가 500~599(529 포함)이면 일시 원인으로 판정합니다. 숫자와 숫자 문자열을 함께 받고, 도구 결과나 중간 프레임 안의 상태는 읽지 않으며, 429 와 한도 종료는 지금처럼 한도 경로로 갑니다. 이 판정은 재부착, 리뷰 전송 단절 재파견, 교대 재기동이 함께 읽습니다.

### Why

연결 끊김으로 크래시한 설계 스테이지는 재부착 규칙이 429 가 실린 크래시만 받아 재부착 밖으로 떨어졌고, 남은 새 파견은 이미 저장된 문서 앞에서 문서 존재 가드로 멈춰 런이 사람을 기다렸습니다. 또 일시 원인 판정이 상태 코드를 429 를 거르는 데에만 써서, API 500 으로 끝난 크래시가 일시 원인이 아닌 것으로 기록되어 재기동·재파견 경로를 타지 못했습니다.
