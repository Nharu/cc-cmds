등급: patch

티켓 배달 하위 런에서 설계 생략을 확정해도 진입 판단이 넣은 시각 단계가 그래프에 남습니다. 화면을 만드는 계획에 시각 단계가 빠졌으면 킥오프가 시각 단계를 넣을지 묻습니다. 그래서 화면 작업이 시각 검토와 화면 승인 없이 머지되는 일이 없어집니다.

### Fixed

- **설계 생략 재작성이 시각 단계를 지우지 않음** — 설계 생략을 확정하면 그래프를 `implement` → `review` 로 덮어쓰던 것을 고쳐, 설계·감사 단계만 지웁니다. `S2V` 는 선행 없이(`depends_on` `[]`), `S2P` 는 `S2V` 에 기대어 남고, 구현 단계는 `S2V` 에 기댑니다. 계획에 `S2V` 가 있으면 생략 질문에 시각 단계가 남는다는 한 줄을 더합니다.
- **생략 경로의 `대상 화면`** — 설계 생략이 확정된 런에서는 `대상 화면` 을 목록으로만 받고 `설계에 위임` 을 내보이지 않습니다. 상위 티켓 블록에 화면 id 꼴의 뚜렷한 후보가 있으면 첫 선택지로 추천합니다.
- **진입 판단 프롬프트의 시각 단계 안내** — 설계도 감사도 없는 그래프에서는 시각 단계에 선행이 없다(`depends_on: []`)고 안내합니다.

### Added

- **킥오프 Step 3 의 시각 단계 확인** — 계획에 `S2V` 가 없고 설계 문서의 슬라이스가 화면 id 를 적었거나 시각 사이드카가 있으면, 또는 과제·판단 사유·상위 티켓 문면이 화면 작업을 말하면, 질문 칩 `시각 단계` 로 `시각 단계 추가` 와 `없이 진행` 을 묻습니다. `base` 그래프, 티켓 배달 그래프, 구현 단계가 없는 계획에는 묻지 않습니다.
